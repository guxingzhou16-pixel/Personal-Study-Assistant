决策日期：**2026-10-15**。用户要求简化发布流程，以**完成并发布第一版可本地下载安装的 Windows 学习软件**为当前主要目标。本文是当前发布路线、门槛和优先级的依据；README 顶部保存功能状态，历史报告保存各自候选及验证证据。

## 1. 交付目标与范围

- 交付 Windows x64 NSIS 安装器、GitHub Release 下载入口、版本/安装说明、SHA-256，以及适用的许可通知和第三方源码获取材料。
- 首发采用明确标注的未签名预览版，通过GitHub直接下载；预览标记不缩减首版功能范围，也不豁免具体分发条件，不新增商店路线。
- 首版沿用现有阅读、聊天/资料问答、本地混合检索、笔记/反馈、练习/手动复习、受控路线/确认写入、计划/番茄钟/成果、主题、历史及完整备份恢复。实现和验收边界见 [README](../../README.md#功能实现与验收状态)。
- 冻结功能范围，只处理影响交付的缺陷、依赖分发、安装体验和说明。不得为了赶发布默默删除 PDF、本地模型或混合 RAG；确需替换模型/依赖或调整承诺时，说明影响并完成相关验证。
- “首版”指第一次公开交付的范围，不强制把当前 `0.1.1` 改为 `1.0.0`；最终版本与包内元数据、源码标签一致。不承诺任意模型、学科和机器上全部正确。
- 本轮是文档与政策更新，没有生成新包、上传安装器或创建发布标签，不能当作发布回执。

## 2. 技术与环境：区分开发和使用

继续使用 Electron + React + TypeScript、Vite/esbuild、SQLite/FTS5、PDF.js、安全 Markdown、Transformers.js/ONNX Runtime/BGE 和 RRF。密钥沿用 Windows DPAPI，安装器沿用 electron-builder/NSIS。版本与命令以 `package.json`、锁文件和 `electron-builder.json` 为准，不更换架构或增加服务器。

| 环境项                              | 开发/构建                                              | 下载后的普通用户                                           |
| ----------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| Windows x64                         | 当前构建目标                                           | 当前支持 Windows 10/11 x64，已验机器看报告                 |
| Node.js ≥24.16、npm、Git            | 需要，使用 `npm ci` 锁安装                             | 不需要另装，运行时随应用提供                               |
| Rust、Python、C++ 编译工具          | 日常开发与现有预编译依赖不要求；第三方材料整理工具另计 | 不需要                                                     |
| Microsoft Visual C++ v14 x64 运行库 | 原生 ONNX 推理需要可用运行库                           | 本地语义检索可能需要安装/更新；不是 Visual Studio 编译工具 |
| Ollama 与聊天模型                   | 验证本机聊天时准备                                     | 选择本机聊天时自行准备，也可自行配置兼容远程接口           |
| BGE 检索模型                        | 语义测试时准备固定权重                                 | 可选下载约23.3 MiB，不随安装器捆绑；缺少时保留关键词检索   |
| GPU/CUDA                            | 当前文本嵌入使用 CPU                                   | 不设为软件统一前提，聊天模型资源需求单独说明               |
| Sandbox/测试用户/虚拟机             | 正式包隔离验收选用一种即可                             | 不需要                                                     |

不增加注册账号、云端数据库、收费服务、Docker 或独立部署后端。首次下载软件/模型需要网络；准备完成后，本机模型与资料可在本地使用。最低内存、显存和最大资料规模以实际测量为准，不编造指标。[ONNX 运行库要求](https://onnxruntime.ai/docs/install/)

每项缺口记录“实际随包对象 → 适用条件 → 已有依据 → 剩余动作 → 关闭证据”。已有明确许可时依条款处理，不要求每个上游另行审批。维护者需亲自接受新协议/责任或付费时明确提出，普通资料核对自行推进。隐藏按钮但继续捆绑组件不能声称已移除分发义务。

## 5. 最短交付顺序

1. **确认首版范围和剩余清单。** 对照 README、Git 和实际源码，复用已交付功能，不再新增模块。
2. **完成三项具体分发处理。** 复用现有材料，交付必要通知、源码索引/归档和说明。外部答复未到时继续独立事项，并评估可结束缺口的替代方案。
3. **冻结最终源码，构建一份 NSIS 包。** 从明确提交的干净隔离源码锁安装，使用 `npm run desktop:dist`；它是未签名入口，不改用要求证书的命令。保留旧候选及失败范围，不每改一份材料就生成新包。
4. **验证受影响行为及最终包。** 纯通知改动核对字节/路径/许可载荷，依赖或功能变化才补对应 PDF、推理、迁移与交互验证。最终包在真实隔离 Windows 环境验证安装/启动、代表性学习流程、必要模型/资源、重开及卸载数据行为；有效且未受影响的历史基线不全部重做。
5. **发布 GitHub Release 并独立核对。** 使用已授权仓库/分支范围，提供确切源码标签、安装器、SHA-256、必要许可/源码附件或可取得链接、版本说明及未签名提示；核对实际上传字节与下载可用性。仅上传源码 ZIP 不算软件已发布。
6. **确认首版完成，再安排增强。** 保存发布 URL、标签/提交、最终包摘要、验证范围和已知限制；随后收集使用反馈，另排签名、网站及其它功能。

历史推送/发布授权按实际范围继续有效，不重复索取同一授权；未授权的 main 合并、付费、身份提交或第三方联系不自动包含在本计划中。本次文档更新不执行外部发布动作。
