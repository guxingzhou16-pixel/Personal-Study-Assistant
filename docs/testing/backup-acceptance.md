# 完整学习数据备份与恢复：独立验收清单

## 状态与测试边界

本清单于 **2026-10-05** 创建，功能代码已接入，**以下功能项全部未执行**。主线仅做类型、生产构建、源码格式和静态审查，没有启动应用、运行功能测试、打开个人数据库或调用模型。本文件是交接要求，不是测试通过报告。

当前完整备份格式为 **1**，只支持主库 **v11** / 活动库 **v1**；派生索引仍为 v2，不导出、不新增迁移。七个具体桥接为 `backupState`、`exportBackup`、`inspectBackup`、`confirmRestore`、`discardRestore`、`cancelBackup`、`onBackupUpdate`。实际业务流程与手动回退见 [README](../../README.md) 的“完整学习数据备份与恢复”。

测试只使用可生成资料、独立临时目录及 `STUDY_COMPANION_DATA_DIR`。不得读取、移动或删除 `%APPDATA%\StudyCompanion`、私人学习资料、真实密钥或真实模型；不得为了验收恢复而启动个人数据库。退出、磁盘写入失败、等待记录与回退也在临时目录验证。

## 1. 固定样本与往返基准

- [ ] 记录被测提交、Electron/Node/Windows 版本、临时数据根目录、备份目标及应用启动方式。测试不同提交时记录各自结果，不复用历史通过数量。
- [ ] 生成含中文标题/书签的多页 PDF 与含标题、表格、代码的 Markdown；完成导入、各自阅读位置与引用。样本不得依赖远程图片、私人文件或付费接口。
- [ ] 准备已保存笔记及专用反馈、普通会话/资料问答、学习路线/所选记忆、不同范围记忆、项目/任务/任务来源、专注终态/复盘、签到/按日累计时间、学习偏好。使用可控模拟内容；恢复本身不需要运行模型。
- [ ] 留存导出前逐表记录、rowid/稳定顺序、UUID、revision、时间、关联、出处原文/位置及文件摘要基准。往返核对原值，不能只检查预览数量或页面有内容。
- [ ] 包含空数据库/零资料、只有扫描页的资料、已删除来源的历史出处/任务来源、重复 PDF 书签、空书签标题、合法无标题 Markdown/无文字段落以及 stopped/error/interrupted 的部分回答，避免校验误拒绝已有合法数据。
- [ ] 准备只在内存中的未保存草稿、未确认记忆/任务提议、派生索引、本机模型目录、假密钥密文和旧迁移备份哨兵；不使用真实密钥。用于证明哪些内容没有导出，不把它们当作备份包的允许额外文件。

## 2. 完整导出

- [ ] 从传统根目录和已经恢复后的 active 学习目录各导出一次。导出当前实际学习数据，不能仍读取旧根目录或混用两个目录的库/资料。
- [ ] 导出目标新建独立 `拾知备份-时间-标识/`，重复导出不覆盖旧包；取消原生选址不创建成功记录或改学习数据。
- [ ] 完整包恰好包含 `manifest.json`、两个独立数据库及 `sources/`。两个数据库脱离原 WAL/SHM 后可完整读取，保存原 rowid 和相同值/关联，不因重建导致会话轮次顺序变化。
- [ ] 清单的格式、应用标识、创建时间、版本、九类数量、每文件大小/SHA-256 与实际一致；每个数据库引用的资料副本存在、名称和内容哈希对应。缺失/被修改副本导致整次失败，不能导出“成功但不完整”的包。
- [ ] 导出两库期间业务不能继续写入；读到的任务/聊天/学习日历与基准属于同一个静止状态。检查导出不改变任务完成、计时、签到或专注终态。
- [ ] 确认没有密钥及密文、本机模型、检索索引、日志、旧备份、未保存稿或未确认提议；偏好及已保存的历史记忆/反馈仍在。备份不加密的提示明确，目录被选在可信外部位置。
- [ ] 处理中清单尚不存在；清单最后完成，worker 实际退出后才发布最终目录与成功状态。程序不把隐藏的部分目录当作已完成备份。
- [ ] 在总大小超限时复制资料前拒绝；单库 2 GiB、资料 10000 份、总文件 50 GiB、清单 3 MiB、单份原导入限额均有边界。小规格用可控文件/注入验证，资源上限实测单独记录，不默认创建几十 GiB 文件。

## 3. 格式、文件与数据库拒绝项

- [ ] 缺失清单/数据库/资料、无效 JSON、空文件、大小或哈希错误、重复条目、数量不符、错误应用/格式或主库活动库版本、未知字段/类型均失败；当前学习数据及原备份保持不变。
- [ ] 验证 `../`、绝对路径、盘符、反斜杠、Windows ADS、大小写不合约哈希、伪造扩展名及数据库以外名称，不能读写允许目录外文件。
- [ ] 包根目录的额外文件或嵌套目录、sources 额外/缺失/重名文件、符号链接/目录联接/硬链接全部拒绝；入口、源文件和清理目标都必须保护。只检查字符串路径前缀不算通过。
- [ ] 应用数据根目录及其内部目录不可作为导出父目录或恢复来源；通过链接指向该目录也拒绝。用户选择父目录和原备份不得被递归清理。
- [ ] 清单读取始终有 3 MiB 上限，读取期间增长也不能无限分配。异常多文件/字段/字符串/记录不能绕过限额。
- [ ] 文件即使重算散列仍须校验 SQLite quick_check、外键和精确 sqlite_schema。额外表/视图/索引/触发器（包含试图借 sqlite 前缀绕过的对象）、缺失约束、错误列及伪造版本不能恢复或执行外部结构。
- [ ] 无效设置/模型地址、笔记/记忆/计划/专注的非法字段或关联、非法日历日期/签到值/时长、错误 UUID/revision/时间均拒绝；schema 正确不能代替逐行检查。
- [ ] 资料名称/格式/字节数/页数、outline 深度/页码/行号、segment 锚点/类型/文本、阅读位置 page/anchor/offset/zoom/tone 有效。`position.extra`、`tone` 数组/对象、越界页码或不存在锚点拒绝，合法位置恢复后仍能保存。
- [ ] 聊天证据对象/数组/文字类型、顺序编号、页码/行号/锚点、UTF-16 偏移/长度、片段长度、source 名称/hash/kind 均检查。`evidence = {}`、null 条目、错误 number/text/offset 拒绝，不能先报恢复成功再在页面读取时崩溃。
- [ ] 普通/笔记反馈/学习路线用途与相应快照一致，双快照或错误 note_id 不接受；无活动专注/streaming 轮次。历史不存在的来源允许留作溯源，不伪造可用引用；合法空答案/通知、旧文字中的合法控制字符和空书签不得误拒绝。
- [ ] 只有一份主库迁移前备份、旧/新完整备份版本均显示不支持，不能改 user_version 强行恢复或自动清空。后续增加版本支持须有真实旧结构夹具及兼容记录。

## 4. 维护锁与取消

- [ ] 首页计时 running、focus running/paused、导入、检索/重建、聊天生成、模型下载及其他未完成 IPC 时拒绝开始；不自动暂停/完成/重开任务，不自动增加或清空时间。
- [ ] 操作开始后全局处理弹窗使其他页面不可操作；主进程同样拒绝普通 IPC，不能只靠按钮 disabled。状态读取/取消可用，非主窗口/子 frame 调用仍被拒绝。
- [ ] 两次开始/确认/放弃、按钮连点、相互重叠 IPC 不创建第二个 worker/目录/恢复；busy 和 revision 显示实际状态，不用局部旧状态覆盖新结果。
- [ ] renderer 重载时 bootstrap 可能因维护锁失败，但独立 backup 状态订阅仍显示处理中且可以取消；结束后可重试启动加载，不自动重发导出或确认。
- [ ] 原生选址窗口未关闭时取消、选址后/新目录建立期间取消、文件复制/数据库检查期间取消、worker 已返回但尚未最终写入时取消均有明确结果。取消窗口需要关闭原生对话框，不能误报已经结束。
- [ ] 取消/故障 kill worker 后必须等 exit 才解锁或清理，避免 Windows 文件锁/晚到写入。取消只删除本次尚未活动的 UUID 子目录，不删除原文件、父目录、active 或 pending 指向的数据。
- [ ] 导出目录改名或恢复 pending 最后写入前进入 commit，不可取消；恢复 restart 阶段也不可取消。验证竞态不会出现“取消成功”同时写入 pending、自动恢复或导出成功。
- [ ] 清理失败明确提示并保留可诊断副本；启动失败、worker 崩溃/异常输出、30 分钟超时、磁盘空间/权限/fsync/部分写失败不显示成功，旧数据保持可用。
- [ ] 非 restart 阶段关闭窗口阻止退出并说明等待/取消；强退可能留暂存，重启不把无 pending 的孤立目录当作恢复或新学习目录。

## 5. 预览、放弃与确认

- [ ] 选择完整备份后复制到根目录 `learning-restores/UUID/`，只校验这份隔离副本；预览九类数量、体积、时间、十分钟有效期与整份替换/未保存丢失提示。
- [ ] 原外部备份在预览后修改不改变隔离预览；隔离副本/清单后来改动、损坏或过期拒绝确认，不能沿用已显示数量承诺新内容。
- [ ] 同时只缓存一份，新预览释放旧副本/旧 ID；取消选址不消费旧预览，确认/放弃不接受任意 UUID、renderer 路径或自造清单。
- [ ] 放弃和未确认预览正常退出不写 active/pending、不触发重启。退出时即使后来开始计时或聊天也能清理预览；清理失败被捕获并报告，不形成未处理 Promise 拒绝。
- [ ] 勾选输入已保存后仍需原生默认取消确认；取消确认不切换、不消费可重试预览。dirty 笔记需先保存/放弃，其他未保存稿丢失提示明确，不称自动保存。
- [ ] 确认期间过期或副本变化、业务不空闲、位置已变、已有 pending、写入失败都返回具体错误并保留旧数据；不能重复确认同 ID 写入第二个等待操作。
- [ ] pending 持久写入成功后预览已消费、显示等待重启；失去 IPC 应答/切页/重载不能撤回或重发。用户重新读取状态得到实际情况，自动重启失败可手动退出重开，不重复写记录。
- [ ] 恢复没有合并、重新执行模型/任务提议、发送历史数据、自动继续聊天/专注或下载模型；确认成功不等于已完成启动切换。

## 6. 启动切换、故障与旧数据保护

- [ ] 在干净临时根目录恢复样本，再核对两库所有基准值、文件、阅读位置、出处、会话顺序、笔记/计划/专注/日历和偏好。旧根目录库/资料仍在，before-restore 为 null，receipt 与实际 active 目录一致。
- [ ] 根目录 → 恢复目录 A → 恢复目录 B 连续恢复：各自旧目录保留，准确旧 pointer 可找回；两库/Files/Search 使用新目录，Credentials/Embedding 始终使用根目录。不混用两份数据，不把根目录旧库误当正在更新的库。
- [ ] 启动处理 pending 时再次校验完整副本；成功打开两库/恢复基础状态之后才写 active。fsync/rename、候选开库/读取失败及阶段间中断只产生旧或完整新状态，不产生一新一旧组合。
- [ ] 切换前失败隔离等待文件为 failed 名称并说明继续旧数据，保留 stage/原库，不自动反复恢复。隔离失败说明实际状态并保留文件，不用“成功”掩盖故障。
- [ ] active 已提交但 pending 清理失败/退出：下一次相同 ID 只清理等待记录、不重复验证旧 manifest 或应用恢复；清理仍失败时提示已恢复且当前新目录正常，不误报回到旧库。
- [ ] active 文件损坏/链接、错误 UUID、指向缺失数据库/资料目录或非法 previousId 时拒绝创建空库代替。错误启动不删除 active/旧数据，不悄悄落回默认空目录。
- [ ] 恢复后新增/编辑/计时数据写入新目录，不修改保留旧学习内容；派生索引按需在新目录重建，缺模型时关键词仍可用。本机假密文保持原样，跨机器不认为密钥随备份转移。
- [ ] 强退遗留隔离副本/旧数据不会被自动删除或意外使用；正确提示磁盘占用限制。常驻状态/恢复回执的显示依据保存 pointer，不虚构成功时间。
- [ ] .gitignore 排除恢复目录、active/pending/before 指针及临时文件、完整备份文件夹、数据库和密文；源码与清单本身可提交，不追踪测试数据或私人内容。
