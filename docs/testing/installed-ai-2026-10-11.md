## 执行方式与隔离边界

新增入口复用 `scripts/installed-acceptance-smoke.mjs` 的既有 WDAG 身份／SID、系统 KnownFolders、ProfileList、安装注册项、非链接路径、正式 `app.asar` 和 `app.isPackaged` 核对。三个阶段使用独立的 `installed-ai-expected.json`，不需要重做旧的 `create` 资料／计划／番茄钟基线。

`ai-create`运行旧`7fdf3fe`静态候选并绑定`plan.previous`；保存后实际替换为新冻结候选，`ai-restore`与`ai-verify`的运行时身份绑定`plan.current`，保存数据仍与旧创建快照完整比较。两包均0.1.1，本轮仅称同版本源码替换，不冒称跨版本或旧schema迁移。原0.1.0→0.1.1链不重复执行。

仅在新的真实 Windows Sandbox 内执行以下命令，不能从宿主运行该脚本或正式安装包：

```powershell
node C:\AcceptanceInput\installed-acceptance-smoke.mjs --stage ai-create
# 外层实际将旧候选替换为新冻结包，再继续以下阶段。

# 外层先实际卸载、逐文件核对用户数据，再重装同一冻结包。
```

离线只读输入包括冻结包、Node／Playwright、五个固定 BGE 文件及官方签名的 Windows 运行库安装程序。运行库只能在 guest 安装；不得在宿主安装、修改系统 DLL，或把 DLL 手动塞进应用目录。结果写入新 UUID 证据目录，每个阶段生成独立 `ui-<stage>-<UUID>/result.json`；原始结果保留，不覆盖或删掉失败。

生成服务限定为 guest 内 `127.0.0.1` 的合成接口和测试假密钥。只有 `ai-create` 可响应四个确定的 `/v1/chat/completions` 请求；重开／恢复／重装验证只允许检测模型列表，不允许再次生成。真正的 CPU 检索使用正式包的 ONNX utility 进程和固定 BGE 权重，不替换推理实现、不访问互联网、不下载模型、不调用收费 API。

原生文件／文件夹选择和恢复的最终系统确认使用受限的 dialog 替代；学习任务与记忆确认使用真实渲染界面按钮。记录应明确写“自动化选择／确认”，不能称为人工鼠标操作。

## 合成场景与断言

- 唯一资料原文为“事务必须全部提交，或者全部回滚。数据库索引使查询更快。”，唯一笔记包含尚待核对的错误理解。
- RAG、笔记反馈和路线故意返回不连续于原文的引句 `“事务只提交一半。”[1]`；断言完成状态保留原回答，出现连续原文核对警告，且有效 `[1]` 能解析到真实资料锚点。
- 笔记反馈另有故意不存在的 `[99]`；断言未知引用警告、解析拒绝、恢复后的界面没有“引用 99”按钮。这些假答案用于检查协议、存储、引用和警告，不用于声称模型的语义质量。
- 生成／起草／预览后记忆与任务仍为空；通过两个独立确认按钮才写入一条 `learning-route`／`local` 学习意向记忆和一项有路线 ID／revision 的 `todo` 任务。
- 完整备份应有一份资料、一份笔记、四个会话、四个轮次、一条记忆、一项任务；项目、专注和学习日记录为零。备份不包含密钥或模型。
- 独立快照保存设置、原文资料／阅读位置、笔记四字段、普通会话／资料问答、反馈的笔记快照、路线请求／证据／回答、记忆与任务完整来源。只排除既有基线中读界面会变化的资料 `openedAt`；其他保存字段逐项保持。
- CPU 查询使用换说法“怎样让查找更迅速？”，要求返回真实“数据库索引使查询更快。”片段，包含混合检索说明且没有关键词降级、失败、退出或超时说明；前后核对所有五个模型文件的字节与固定 SHA-256。
