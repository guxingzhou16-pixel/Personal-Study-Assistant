## 2. 确认的代码问题

### U-01：普通英文表达导致相关资料全部被过滤

**版本：当前未发布修复的回归；已发布冻结源码在这个英文例子中能找到证据。建议先修这一项，再发布维护版。**

复现：导入内置“拾知学习示例”，在资料问答中移除选文限定，指定该资料，分别检索：

| 问题                   | 当前关键词 | 当前真实 BGE 混合 | 发布冻结源码关键词 |
| ---------------------- | ---------: | ----------------: | -----------------: |
| 解释主动回忆           |       3 段 |              3 段 |               3 段 |
| 请用 demo 解释主动回忆 |       0 段 |              0 段 |               2 段 |

当前关键词路径中，“请帮我 review 一下主动回忆”也为 0 段。混合路径明确报告本地混合检索，没有降级，仍然是 0 段。

原因：`electron/core/retrieval.ts:22` 的 `matchesNamedQuery` 在含中文的问题里，将长度大于一且不在有限停用词表中的英文词都当成必须匹配的名称。资料没有 `demo` / `review` 时，在 `retrieval.ts:201` 丢弃候选；`electron/core/vector-retrieval.ts:188` 对语义候选执行同样过滤，语义结果也救不回来。

影响：用户只是提出举例／复习方式，系统却说找不到原文；后续进入空证据说明路径，不能基于已有定义回答。

建议：区分请求方式和真正的技术名称，收窄强制过滤条件；保留针对无关技术主题的保护。补充未参与此前调参的中英混合问句，并同时验证关键词与混合路径。

证据：`independent-retrieval.json`、`independent-hybrid.json`、`released-code-comparison.json`、`07-demo-no-evidence.png`。

### U-02：复习页持有旧作答版本，提示重读却没有保留草稿的恢复入口

**版本：当前版桌面复现；`ReviewsPage.tsx` 与发布冻结源码相同。此前的修复给测验页增加了读取最新作答，反向流程仍有缺口。**

复现：

1. 在真实生成的短测验中保存第 1 题作答，版本为 1。
2. 打开轻量复习，选择该题，让编辑器读入版本 1。
3. 返回测验，修改并保存同一题，数据库成为版本 2。
4. 回到轻量复习，开始回忆并写入新答案，点击保存。
5. 持续提示“作答已更新，请先重新读取；当前输入仍保留。”；再次保存仍失败。点击列表中的同一题，只提供放弃当前输入后重新打开的确认。

原因：`src/components/ReviewsPage.tsx:29` 在页面再次可见时只更新 `records`，没有更新当前编辑记录的版本；`ReviewsPage.tsx:73` 仍提交旧 `current.revision`。页面也没有与测验页对应的“保留输入并读取最新版”操作。

影响：数据库正确拒绝覆盖新答案，但用户难以继续保存这次回忆。当前草稿没有立即被删除；本轮没有将其记为已经发生的作答丢失。

建议：给复习页补齐保留草稿的重读与比较选择，或者在无草稿时同步最新版；保留主进程的版本冲突保护，不自动覆盖或自动重发。

证据：`review-reverse-conflict.txt`、`review-recovery-dialog.txt`、`16-review-reverse-conflict.png`。保存数据仍为版本 2，与被拒绝的第三次回忆区分保存。

### U-03：路线批量保存成任务后，步骤顺序变成随机 ID 顺序

**版本：当前版桌面复现；相关存储与计划页实现和发布冻结源码相同。**

复现：真实路线先安排步骤 1“阅读原子性定义与要求”，再安排步骤 2“准备解释案例与实例”。按此顺序勾选、预览并确认新增两项任务。预览正确，计划页与首页却显示：

1. 准备解释案例与实例——原步骤 2。
2. 阅读原子性定义与要求——原步骤 1。

原因：`electron/core/planning-storage.ts:342` 给同一批次使用完全相同的创建时间，每项任务各自生成随机 UUID。`planning-storage.ts:180` 的列表查询按创建时间、ID 排序；`src/components/PlanningPage.tsx:53` 也在创建时间相同时按 ID 排序。本次两项创建时间均为 `2026-10-16T10:01:27.997Z`，因此随机 ID 决定了先后。

影响：路线中的前后关系在日常执行入口丢失；重启并不会恢复原始顺序。任务正文仍有步骤编号，记录内容没有丢失。

建议：采用最小的稳定顺序方案保存批次内次序，让数据库查询、计划页和首页一致。验证预览、确认后列表以及重启后列表均保留选择的路线顺序，不能只断言新增数量。

证据：`route-task-confirmation.txt`、`route-task-order-ui.txt`、`before-restart-complete.json`、`after-restart.json`、`14-route-task-order.png`。

### U-04：首页日历的隐藏状态文字撑开外层页面，出现双滚动条

**版本：当前版与发布冻结源码均观察到外层多余滚动。**

现象：正常和最小窗口中，主内容区已有滚动条，窗口最右侧又出现一条整页滚动条。最小窗口内容高度为 601 像素，`documentElement.scrollHeight` 却为 1296 像素。

定位：`src/components/StudyCalendar.tsx:247` 使用 `.sr-only` 放置状态文字；`src/styles.css:1592` 将它设为绝对定位，但日历区域缺少对应的定位容器。该不可见元素的静态位置在内容下方，影响了外层滚动范围。

只在试用窗口临时做的诊断：隐藏日历内这条 `.sr-only`，或给 `.daily-section` 添加 `position: relative`，文档高度立即从 1296 回到 601。诊断样式随后恢复，没有写入源码。发布冻结目录也观察到文档高度 1279、视口高度 861 的额外滚动。

建议：限定这条隐藏状态文字的定位范围，保留其无障碍播报用途。验证两种窗口下只有预期的内容滚动，侧栏与页头不会随整页产生额外位移。

证据：`layout-diagnosis.json`、`01-first-home.png`、`10-home-minimum.png`、`released-code-comparison.json`。

## 3. 用户体验建议

这些是改进建议，与上面的功能缺陷分开，不表示本轮已实现。

1. **把首次引导放到第一屏。** 空白数据首次启动时，引导顶部约在内容坐标 1803 像素，第一屏只有欢迎卡片和空任务。`src/App.tsx:498` 当前把它放在日历与学习流程之后。建议首次启动优先展示“导入示例 → 选模型 → 第一次问答”，用户完成后再收起。
2. **让等待可以理解。** 首次问答在 72 秒时仍无可见答案；短测验在 73.6 秒时也仍无可见输出，之后均成功完成。当前 `chat-stream.ts:60` 只将可见正文交给界面，`ModelAnswer.tsx:40` 只显示等待文字。建议显示真实已用时和可确认的处理状态，持续提供停止入口，并提示慢模型可以换小模型。这是本机 9B 模型的观测，不能推断所有机器或云服务都慢；也不应编造百分比或展示模型内部推理正文。
3. **简化路线操作和说明层级。** 生成结果后既要确认路线、又要任务预览、再最终确认；重复说明很多。可以让前置核对与预览衔接更直接，同时保留最终完整写入预览和明确确认。
4. **资料库提供处理误导入的路径。** 当前可以导入、搜索和阅读，但没有移除资料／重命名入口。实际使用容易遇到导错文件或版本过时；后续设计需明确已有笔记、引用与备份的保留规则。
5. **跨页显示当前专注。** 计时能在阅读期间继续，但离开专注页后，缺少明显的全局倒计时／暂停入口。适合增加简洁的进行中提示，减少为了查看剩余时间反复切页。

另一个检索边界：“解释主动回忆，给个例子”在当前与发布冻结源码的关键词路径均为 0 段。它与 U-01 的新增英文强制过滤不同，反映了现有覆盖率阈值对自然表达仍较敏感；本轮没有单独证明混合路径中该中文例子的行为，也没有据此宣称一般检索质量不合格。

模型内容观察：真实路线共四步、合计 20 分钟，关联编号有效，并明确资料缺少 SQL／环境说明。不过复盘步骤出现“全部成功和全部失败”的表述，容易混淆“任一步失败即全部回滚”。这是实际生成内容的用词风险，不是已经证明的解析器缺陷。结构与预算检查通过后仍需要用户核对语义。
