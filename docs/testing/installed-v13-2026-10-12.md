## 6. 失败与最小修正

1. 尚未登录的 Sandbox CLI 首次 Inspect 返回 `0x80070520`，尚未执行业务；连接同一实例后才继续，原日志保留。
2. 首次旧备份恢复在设置页触发 `backupBusy`，尚未开始解析或写入 pending。两个设置组件分别异步校验固定模型文件；脚本原来没有等待。仅等待 `.model-health` 与 `.embedding-settings` 都显示完成后请求一次备份；保留产品占用锁、超时和失败断言。原 FAIL / 截图与原两脚本字节保留，独立重试才记 PASS。
3. 首次 `v13-create` 在开始专注前，脚本“任务日期”定位同时匹配计划页与隐藏挂载的专注页。只限定 `.planning-datebar`；原 FAIL / 截图保留。此前已导入示例，因此通过显式 `v13-reset-legacy` 真实恢复旧备份后才重试，不直接删数据或改写黄金回执。

专用重置必须有同源码 / 同 guest 的失败创建回执，且不存在成功 v13 黄金记录；复用真实恢复和完整旧数据比较。它仅重置本次合成资料，不是产品的新功能。QA 修正不改变冻结安装包，也不降低产品断言。

guest PowerShell 5 捕获 Node stderr 时留下 CLI XML 解析警告；保留原日志。是否通过同时核对 SDK JSON `ExitCode`、Node 退出码和业务 result，不把宿主 `$LASTEXITCODE=0` 当成 guest 业务成功。

后续创建尝试的失败同样保留：

- 初始 Markdown 可见后立即程序选文，蓝色 Range 保留但提问按钮未启用。源码有初始化滚动清除 quote 的路径，但未取得失败时的事件顺序，不将根因断言为已确认。只在选文前完成浏览器滚动帧、核对选文 footer，随后一次选文和正常点击；下一次通过该门槛。
- 同一会话的旧答和新答都含引用 1；脚本严格匹配冲突。改为本次确切回答段落中的引用，不选任意最后按钮，不改旧历史。
- 会话创建按钮实际名为“新会话”，脚本旧名称不匹配。仅修正文案定位。同时发现旧未发送 Markdown 问题会触发替换 PDF 选文的确认；脚本先完成草稿保留检查，再明确清空该问题。PDF 增加确切资料名 / 第 2 页 / 选文和证据断言，不能将旧通用预览谓词写作 PDF 问答已通过。

每次部分创建后先使用独立真实恢复清理本次合成记录，再重试；所有 FAIL、原输入字节和新修订散列保留。没有自动无限重试、重选或强制点击。
