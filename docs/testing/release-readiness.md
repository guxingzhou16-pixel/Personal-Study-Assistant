## 3. 测试顺序与记录

1. **先核对产物，再隔离数据。** 记录完整提交、安装器摘要、Windows/Node/工具版本；正式包测试用独立Windows用户或可恢复VM。仅设置开发数据目录环境变量不能隔离正式包。
2. **先验数据，再验交互。** 在合成旧数据上验证迁移与备份/恢复；失败保留两库、资料和位置记录。主线不启动程序、安装器、SQLite或模型代替测试方执行。
3. **先验手动流程，再验AI分支。** 使用对应详细清单，记录取消、保存失败、版本冲突和迟到结果。模型列表成功、引用编号存在、回答完成各自不能推导为真实理解正确。
4. **最后验安装版与规模。** 从源码之外启动两种候选，在同一固定版本中完成完整流程、原生资源运行及升级/卸载；同版本重装不代替跨版本升级。
5. **汇总失败与修复。** 未执行/失败保持原状。功能修复须有新提交、新候选和相关复验，不在旧候选记录里偷偷换源码或包。发布前重新核对批准的版本、许可、远端CI与用户授权。

- 数据丢失、错恢复、隐私越权、取消后误写、计时误完成或安装数据保护失败时，先保留证据和旧数据，修复并重验后再考虑发布；不靠提示文案接受这些错误。
- 当前完整备份只接受主v12/活动v1；旧11/1文件夹须用对应旧版在隔离环境恢复，再由新版前向迁移。不得修改清单/数据库版本号来绕过兼容校验。
- 旧程序不保证能读取v12目录。回退核对须使用对应旧程序及升级前完整目录快照，不能直接把旧EXE覆盖新版后打开个人数据库；目录包含两库、资料及位置记录，凭据受Windows用户绑定。
- 已有旧候选、失败输出及源码快照保留，不自动清理；它们可能占用磁盘。当前0.1.0只是包元数据版本，不能把同名安装器或任意旧UUID当作本候选。
- 本表不触发推送、标签、Release、公开仓库、云同步或网站部署。公开发布须在验收完成后取得用户明确授权。
