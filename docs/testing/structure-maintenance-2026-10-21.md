# 2026-10-21 目录整理与架构复评

本轮以阅读和维护为目标，整理当前脏工作区，不升级依赖、不改业务规则、IPC 或数据库版本，也没有提交、推送或更新安装包。

## 实际整理

- 46 个组件／样式文件归入 `src/components/` 下 13 个功能目录，样式随组件放置，配套调整相对 import。
- 31 个后端核心测试移入 `electron/core/__tests__/`，同步动态 import 与 `vi.mock`。Vitest 的递归发现配置不变；纯规则测试与 Electron 流程保留原归属。
- README 从 1120 行收敛为 101 行的当前入口；AGENTS 从 949 行收敛为 470 行，保留稳定开发约定与当前边界。
- 整理前两份完整文档进入 `docs/archive/`，包括原先未提交的维护说明，链接按归档位置重定位。
- 新增文档索引、使用指南和五份架构地图；组件、业务核心和测试目录各有就地阅读说明。
- 没有文件的旧 `src-tauri/` 空目录树保留到本轮产物目录，不再放在当前项目根目录。未追踪的第三方下载、辅助脚本、个人资料、用户数据和旧发行产物保持原有归属。

77 项文件移动均有清单。对涉及的 63 份 TypeScript 源文件比较去除模块路径差异后的 AST，结构和字面量一致；其余 122 份原源码／样式文件逐字节一致。原有未提交功能修改随文件保留，没有拿 HEAD 内容覆盖工作区。

## 架构判断

继续保留一个 Electron 应用，当前不需要引入微服务、多包工程或新状态框架。现有固定 IPC、worker、独立数据存储和确认写入边界合理。

后续维护压力集中在 `App.tsx` 和 `main.ts` 的职责较集中、`src/lib` 同时放共享契约与界面 hook、全局样式偏大。本轮只理清目录与阅读入口；未来按改动逐步拆职责，不能把移动文件等同于完成了运行时分层。

详见[整体架构与维护评估](../CODEMAPS/architecture.md)。
