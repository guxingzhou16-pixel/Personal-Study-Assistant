## 1. Canvas：已经找到的依据与实际缺口

[微软 SDK REDIST](https://learn.microsoft.com/en-us/legal/windows-sdk/redist)的 Static LIB files 段明确覆盖公开发行 SDK 的 `ucrt/x64`、`um/x64` 目录：在适用条款下，原库构建为程序一部分后可分发。SDK EULA 已在前轮缓存。本轮关闭“是否存在静态 UCRT 分发授权”的资料缺口，不把这一依据扩大为所有 VC 静态库的授权。

固定 Canvas `build.rs` 使用 `clang-cl`，设置 `static_crt(true)`；生产日志有 `cc 1.4.0`、`find-msvc-tools 0.1.9`。这两份已经缓存的源说明如何寻找 MSVC 环境：选中安装后读取默认工具集文件或覆盖值，并查找 SDK 目录。固定镜像同时装有多个工具集，其清单未公布默认文件内容；生产日志也没有实际工具集/SDK 库路径。VS 2026/SDK 26100 家族有依据，具体组件原条款尚不能唯一对应。

当前 STL 主线的 LLVM exception 不能自动替代生产版许可；反过来，也不能假定所有 STL 编译嵌入代码都必须额外提供源码或通知。最终 `.node` 运行库与 Skia 归档的关系按实际链接处理，不强求二者使用同一镜像。

**剩余事项：**取得供方已有记录或原 Canvas #1360 答复中的具体工具集/SDK及组件许可对应，再落实确有要求的下游条件。已有 SDK 条款涉及下游保护和分发方责任；现有安装流程没有对应协议机制。这是需要核实的发布条件，不能用增加一份文件替代，也不在条款适用性未确认时要求用户接受责任。

无需另设精确对象 SBOM、位同重建或完整编译器版权全集作为独立发布门槛。SignPath 的 System Libraries 例外与微软分发权分别判断。
