# 三种视觉主题与偏好：独立验收清单

## 状态与测试边界

本清单于 **2026-10-06** 创建。清爽现代、安静书房、活泼游戏化的选择、保存与启动读取已接入，**2026-10-08 已执行独立源码 UI，确认最小窗口导航 F2 和文字对比度 F3 失败，见末尾执行记录**。主线完成类型检查、生产桌面构建、源码格式、静态色值与代码审查；没有运行功能测试、启动应用、打开数据库或请求模型。本清单不是界面、可访问性或备份通过报告。

主题 ID 为 `modern` / `study` / `playful`，默认 `modern`。`Settings.theme` 与 `responseStyle`、每份资料的阅读护眼分别保存。沿用偏好 JSON 与现有 `saveSettings`，**当前主库 v12 / 活动库 v1 / 派生索引 v2 / 完整备份格式 1**。主题本身没有新增迁移、IPC、依赖、积分或学习统计；v12 来自练习快照，参阅 [练习清单](practice-acceptance.md)。

使用独立临时目录及 `STUDY_COMPANION_DATA_DIR`、合成资料和假密钥。不得打开或修改个人应用数据库、私人文件或真实凭据。主题无需模型；密钥失败分支用可控故障验证，不调用真实/收费接口。功能测试代码及执行由测试对话负责，普通改动只验证相关范围。

## 1. 设置输入与旧数据兼容

- [ ] 记录被测提交、Windows/Electron/Node 版本、启动方式、临时数据目录、窗口大小与缩放，结果附实际证据。
- [ ] 新数据默认清爽现代；三种合法 ID 分别通过主进程设置校验，保存后返回实际设置。主题名称、说明、色块与 ID 一一对应。
- [ ] 用保留其他偏好的真实旧 JSON 去掉 `theme` 字段：启动读取补 `modern`，昵称、目标、回应风格及两套模型配置保持原值；仅启动读取不自动回写 JSON。用户随后保存才持久化新字段。
- [ ] `theme` 已提供但为 `null`、`undefined`（IPC 请求）、布尔、数字、数组、对象、空字符串、未知字符串或大小写变体时拒绝。不能把错误值默认为现代或重置其余设置；未知字段仍拒绝。
- [ ] 验证修改主题没有新增或重建数据库表、改 `user_version`、清空旧数据或生成新的偏好文件/localStorage 缓存。旧版本迁移规格须使用真实结构，不用降版本号模拟。
- [ ] 损坏设置在启动或恢复校验处报错，不能界面先显示成功再重置数据；不把“旧应用不识别新字段”误称为支持软件降级。

## 2. 选择、保存与失败

- [ ] 设置页原生同组单选框只有一个选中；点击完整标签可选，配色示意不代替名称，也不进入屏幕阅读器的选项文字。
- [ ] 只改变单选项时全局主题保持已保存版本，不发送 IPC 或自动保存；点击“保存设置”成功后才切换全局配色。再打开设置显示实际保存选项。
- [ ] 未保存时离开设置或退出再打开，恢复原保存主题；提示没有承诺草稿自动恢复或全局即时预览。
- [ ] 设置保存被主进程拒绝或持久化失败时保留旧全局主题，显示错误，当前草稿仍可修改/重试；不提前显示成功。
- [ ] 偏好保存成功后密钥保存失败：按已保存主题切换，明确密钥失败，读取设置确认偏好确实保存。不能因后续密钥错误显示旧主题或谎称偏好未写入。
- [ ] 保存、连接检测或密钥删除忙时，主题控件继承现有禁用状态，键盘与点击都不能改草稿；完成或失败后可继续操作。
- [ ] 三主题与三回应风格的九种组合可以分别保存；主题不更换模型、回应风格、远程确认范围或系统提示。无需验证真实模型表达来判断主题保存。
- [ ] 浏览器预览沿用默认主题，不能通过“保存设置”持久化；不宣称浏览器草稿选择已经写入桌面数据库。

## 3. 全局配色与阅读边界

- [ ] 三种主题分别检查首页、资料库、聊天、笔记、学习路线、记忆、计划、专注和设置；侧栏、顶部、表单、卡片、弹窗、引用/证据及选中状态使用一致配色。打开页面不改变实际学习记录。
- [ ] 清爽现代保持原有颜色回退和布局；焦点环现在使用主题主色。书房为暖纸/棕色，游戏化为青蓝/橙色，均为浅色，不出现暗色/跟随系统/自动切换入口。
- [ ] 切换主题不改变首页签到/时长、任务状态、专注 elapsed、计划预计分钟、历史回答、记忆范围或路线来源，不添加虚构等级/积分/掌握评价。
- [ ] PDF 原页、文字层位置/选择、翻页、缩放、书签和阅读位置不受主题改变；护眼滤镜按阅读器选择生效，不对原文件或 canvas 内容重新着色。
- [ ] Markdown 正文、标题/表格/代码排版、白纸与暖纸护眼保持阅读器原有规则；主题只改变外围控件，引用原文/位置与复制内容保持原值。
- [ ] 正常、成功、错误、警告、未保存和删除确认仍可区分；危险操作继续保留危险色，PDF/Markdown 格式标识保持原有语义。不能把危险按钮变为普通主题主色。
- [ ] 核对长文本、输入占位、选中/hover/disabled、次要文字、链接、焦点环及深浅背景的真实可读性。静态检查仅在选定色值组合计算比率，不证明整界面符合 WCAG。
- [ ] 样式仅从已打包本地 CSS 加载，无外部字体/图片请求、新动画或因切换产生的模型请求；不存在三套重复页面布局或遗漏主题变量导致文字消失。

## 4. 键盘、窗口与缩放

- [ ] Tab 可到主题组，同组方向键/空格完成原生选择；标签、组选项名称、选中状态可被辅助技术识别，焦点清晰，不只靠色块传达选项。
- [ ] 禁用、错误和保存提示实际可理解；主题切换不把焦点丢到无法操作的控件，不造成键盘陷阱。
- [ ] 在最小 900 × 640 和正常较大窗口、1100px 响应式边界分别检查：较小窗口单列，较大窗口三列，中文说明换行，无新增水平溢出或遮住保存按钮。
- [ ] 在 125%、150%、200% 缩放下核对主题组、设置滚动、弹窗和主要入口；原生 radio 没有被通用 input 最小高度/宽度规则撑大或截断。
- [ ] 检查至少一份较长资料名、昵称和提示；主题不改既有页面布局尺寸，其他页面保持原有可操作性。实际缺陷记录具体页面/主题/窗口，不能用构建通过代替。

## 5. 启动、重载与保存来源

- [ ] 每种主题保存后正常退出/重开，根 `data-theme` 和设置值一致，其他偏好保持；主库不因启动读取主题被重置。
- [ ] renderer 重载后重新从 bootstrap 的实际保存设置读取，不沿用未保存草稿或过期界面状态。启动等待期间可能暂用默认现代，不宣称完全无闪烁。
- [ ] 开发 StrictMode 的 effect 清理/重挂载，以及卸载清理根属性后再挂载，不留下错误主题或覆盖刚保存设置。实际应用重启与开发环境分别记录。
- [ ] 一次失败保存后的退出/重载只恢复最后实际保存主题；若偏好保存成功但密钥失败，则恢复成功保存的主题，不依赖 notice 文本推断数据库结果。

- [ ] 三种已保存主题分别导出、恢复到干净临时目录；主题、回应风格、昵称/目标、两套模型配置与原值一致。备份仍包含偏好、不包含密钥/模型/索引，没有新文件格式。
- [ ] 在合法临时包中把主题改为非法已提供值并重新计算清单摘要：仍被业务校验拒绝，不能仅凭哈希匹配就恢复；旧 active 指针、两库及资料保持可用。
- [ ] 根目录与恢复后 active 学习目录的保存/导出都读取当前偏好，切回旧目录显示旧目录主题；密钥/模型仍在根目录，不随主题或恢复移动。
- [ ] 旧 11/1 文件夹备份本版拒绝，不因 theme 兼容而放宽 schema；对应旧版在隔离环境恢复后再升级到 v12。
- [ ] 确认主题自身不改变主库/活动库/派生版本与备份格式，旧 JSON 缺字段是兼容读取、并非新 schema 迁移；旧程序回退兼容未经验证，不修改版本号强行打开。
