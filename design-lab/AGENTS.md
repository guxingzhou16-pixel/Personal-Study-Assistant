# UI 设计试验场协作约定

本目录专门保存“拾知”Windows 桌面学习软件的视觉概念。继续遵守根目录的产品、安全和本地 Git 规则。

- 用户在本目录请求设计 demo 时，优先静态 HTML / CSS / JavaScript，保持低成本，不接入 Electron、数据库或模型，不引入构建框架。
- 2026-10-18 用户明确选定第一轮 `shizhi.sunny-isle.v1`（03 晴岛原版）替换正式 UI。正式维护先读 `selected-design.json`、`../docs/design/SUNNY_ISLE.md` 与对应交接；第二轮只保留参考。原 `design.json` 的 `concept` 是历史快照，不改其 schema，也不将 demo 当成正式运行入口。
- 每轮使用 `YYYY-MM-DD-主题/`；每套使用独立目录，保留过去的设计。共享样式/交互可以放在该轮 `shared/`。
- 明显标记“概念演示 / 示例数据”。截图、签到、时长、回答和资料都不能作为正式软件已有功能或验收成绩。
- 每套设计必须有 `HANDOFF.md` 和 `design.json`：说明设计目的、参考链接、配色/字体/间距、布局、交互、实现范围、产品接入位置及验证限制。
- 每轮必须有 `index.html` 对比入口、`README.md`、`REFERENCES.md`、`designs.json`、`handoff.schema.json` 和预览图。`design.json` 按 schema 维护，供其他 AI 读取；这是静态档案接口，不是应用 API。
- 2026-10-17 第二轮用户选择第一轮晴岛的排版作为参考：本轮保留顶部导航、欢迎横幅及下方双列，不把原版算作新增风格。新增风格先通过视觉覆盖层实现，保留上一轮原档。
- 按用户要求下载的开源 UI 源码放在该轮 `references/upstream/`，避免纳入主仓库；最小运行 CSS、许可证、来源提交号/摘要及本地展示入口随设计归档。格式化时排除上游资产，避免破坏摘要；不自动执行上游安装脚本。
- 不把示例生成的 HTML 字符串复制到正式 React 页面；正式接入复用已有组件与 `desktop.ts` / IPC。增加学习计划、笔记、记忆等真实写入仍需独立开发与验证。
- 只做相关检查：浏览器切页、交互、桌面最小尺寸 900×640、窄屏和本地文件打开。设计稿不需要触发完整 Electron/模型回归。
- 预览图只截本目录生成的示例内容；不要截图个人桌面或应用私有数据。这里的预览是设计交付资产，不是含用户资料的测试截图。
- 完成后登记到本目录 README，并在项目 README 留下入口。不要因此改写正式软件功能状态。
