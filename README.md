# 私人学习助手（Study Companion）

> **项目状态：阅读、流式聊天、可追溯 RAG 与本地混合检索已完成；笔记、AI 反馈、学习路线、长期记忆及手动项目/每日任务已实现，待功能验收。** 已有月历、签到、计时和加密配置。路线可手选记忆辅助建议，记忆提议经用户预览确认后保存；任务由用户手动安排和完成，Agent 不自动修改计划或进度，也不推断知识掌握。真实生成质量由测试对话继续验收。展示网站最后建设。

私人学习助手是一款以本地数据和个人学习体验为中心的学习软件。它将资料阅读、可追溯的 AI 问答、学习笔记、计划和专注记录连在一起，帮助用户提升注意力和学习效率、理解知识、看见进步，并保持学习动力。第一版以编程与技术学习为主要场景，后续逐步扩展到跨学科资料。

## 本地运行

开发环境为 Windows 10/11、Node.js 24.16 或更新的受支持版本、npm 和 Git。Electron 使用预编译运行时，本阶段开发不要求 Rust 或微软 C++ 编译工具。将来新增原生依赖时须重新评估这个约束。

```powershell
npm ci
npx install-electron --no
npm run desktop:dev
```

首次安装 Electron 需要下载运行时；若下载失败，按 [Electron 官方安装说明](https://www.electronjs.org/docs/latest/tutorial/installation) 配置可用网络或代理，然后重新运行 `npx install-electron --no`。不要将本机代理地址写入项目配置。

开发模式支持界面热更新；修改 `electron/` 后重启开发命令。也可以打开经过构建的桌面版本：

```powershell

npm run desktop:start
```

### 和学习助手聊天

1. 在“设置”选择 Ollama 或兼容 OpenAI 接口，填写地址、模型名称，按需保存密钥，再保存设置。本机 Ollama 需先启动并准备聊天模型；模型列表检测成功不保证模型具备聊天能力。
2. 打开“学习助手”，保持“问答方式”为“普通聊天”，输入问题，点击“发送问题”或按 `Ctrl + Enter`。支持普通 Markdown、表格和代码块；不加载模型输出中的图片、HTML 或外链。
3. 模型回应逐段出现，点击“停止生成”立即停止本应用接收并取消请求，保留已有文本；服务端是否立即停止计算或计费由服务实现决定。每次只允许一个回答生成，切换页面/会话后可回来停止。
4. 新建会话可分开讨论不同主题。问题、回答、模型/服务地址、完成状态都存入本机数据库；退出会中断当前生成，重启不自动重新发送。生成中每 500 毫秒保存一次，异常退出可能丢失最后一次保存后的文本；恢复时标记中断，不伪装成完整回答。
5. 远程服务发送前需勾选确认，明确发送目标、近期会话和可能的服务费用。确认绑定地址、模型与接口类型；主进程再次检查目标地址。Ollama 不携带云端密钥，兼容接口只读取其对应地址的密钥。

**当前边界：**普通聊天不检索资料库；最多携带最近 6 轮已完成的普通问答，历史合计不超过 12000 字符（不是 token 上限），资料问答、停止、失败和中断轮次不进入普通上下文。单次问题最多 4000 字符；每会话最多 100 次提问、最多 500 个会话；删除、重命名、导出和精确 token 预算待后续实现。普通与资料问答共用输出/网络边界：回答最多 64000 字符，网络响应最多 8 MiB，单行/事件缓冲最多 1048576 字符；连续 120 秒无数据或总时长达到 10 分钟会停止并提示。实际上下文窗口因模型而异，超长请求可能被服务拒绝；不会自动换服务或重试付费请求。

### 基于资料提问（本地混合检索 RAG）

1. 导入资料后，在阅读器点击“问这份资料”，会新建资料问答会话并选中该资料。也可以在“学习助手”切换到“资料问答”，选择一份或全部已导入资料。
2. 写清问题，点击“检索原文”。没有检索模型时使用 FTS5；下载后自动使用本地嵌入与关键词融合，不调用聊天模型或读取 API 密钥。首次建立索引显示进度并可取消；用“重建检索索引”恢复派生缓存，结果包含实际降级说明。
3. 查看“本次检索原文”，展开片段核对资料名、PDF 页码或 Markdown 标题行号。每次最多 4 个片段；扫描或文字不完整的资料会提示限制。更改问题或资料范围后需要重新检索，预览有效期为 10 分钟。
4. 点击“发送问题”，模型只收到系统提示、本次问题和预览中的证据，不包含整份文件、整个资料库或旧问答。远程发送前需勾选确认，确认绑定当前模型配置与本次证据；换问题、预览或模型后重新确认。没有匹配片段时直接保存“无法据此回答”的本地结果，不发请求，也不要求先选择模型。
5. 点击回答中的 `[1]` 等有效引用，或下方“查看原文”，返回实际 PDF 页码/Markdown 标题；点击“返回问答”继续。会话保存引用原文、偏移与锚点，重启后仍可打开；打开前检查副本哈希及引用与保存原文的一致性。未知编号显示为普通文本；缺少/含未知引用编号时提示核查。

**关键词路径：**每页/章节最多 800 个 UTF-16 字符、重叠 120，不拆代理对；中文分词/汉字二元词入 FTS5。BM25 前 40 候选经至少 50% 字面覆盖过滤，去重取最多 4 片段。原有接口和评测基线保留。

**混合路径：**向量窗口 384 字符、重叠 64，标题最多 64 字符，每批 8 个，保留原锚点/偏移。查询加 BGE 指令，长问题分窗口、平均并归一化；分词后超过 512 token 则明确降级，避免默默丢弃长页/问题尾部。向量为归一化 Float32，扫描当前模型缓存；全局语义候选最低余弦 0.6，关键词命中的资料可用 0.5 补充同资料证据。前 40 候选与关键词结果用 RRF（常数 60）融合，重叠片段只贡献一次语义排名，最多 4 片段。启发式参数集中在 `embedding-model.ts`，不证明证据充分；无外部向量服务或语义重排模型。

每次资料问题独立检索，避免只说“继续”或“它”。资料是证据，不授予工具权限；生成模型是否遵循提示、结论是否被支持仍待真实聊天与人工评测。OCR、逐句核验、ANN 大规模索引与引用高亮尚未实现。

### 下载独立的本地检索模型

1. 设置 →“本地语义检索”→“下载检索模型”。只获取固定模型文件，不上传问题或资料；显示进度，可取消，切换页面后继续。
2. 文件就绪后自动用于下一次检索；CPU 编码在后台进程运行。本地/云端聊天仍按原配置选择，不强制安装 Ollama。
3. 未下载、文件损坏、加载/推理失败或语义进程退出/超时，明确降级；用户取消检索直接结束，不擅自重试。原资料、旧索引与保存的引用保留。

选型为 [BGE-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 的 [Xenova ONNX Q8 版本](https://huggingface.co/Xenova/bge-small-zh-v1.5)：512 维、512 token、CLS 池化，权重/配置共 **24,451,175 字节（约 23.3 MiB）**。模型为 MIT；发布前保留原作者版权/许可说明。Transformers.js 固定 4.3.0（Apache-2.0），ONNX Runtime Node 1.30.0 使用 [Windows CPU 预编译绑定](https://onnxruntime.ai/docs/get-started/with-javascript/node.html)，本机安装未使用 C++ 编译工具；安装包原生库分发和其他 Windows 机器待验收。

模型仓库固定 revision `75c43b069aac4d136ba6bc1122f995fedcfd2781`，5 文件逐项核对大小/SHA-256，全部校验后替换副本。下载最多 15 分钟，不续传；正常取消/失败清理暂存，保留已有副本，异常退出可能遗留暂存。推理禁止远程模型读取，CPU 最多 4 线程；检索进程 512 MB V8 堆、5 分钟超时，不代表总内存上限。本机 ONNX Runtime 的 Windows x64 原生目录约 64 MiB，Transformers.js 约 9.4 MiB，另有其他依赖；安装包大小与资源裁剪未验证。每次检索重新加载模型，评测的热查询耗时不等于桌面操作耗时。

报告为已忽略的 `artifacts/retrieval-evaluation.json` 和 `artifacts/hybrid-retrieval-evaluation.json`，保留逐题期望/实际锚点、失败项、配置/模型标识、硬件和耗时。退出码 0 不代表每题完整命中；混合评测发生嵌入降级时返回非零，不把关键词成绩冒充混合成绩。缺少权重时要求先下载，评测与真实模型桌面验证不自动联网。普通 `test:e2e` 与真实权重的 `test:embedding` 是不同门禁。

独立数据集 `synthetic-retrieval-v2` 在 `tests/fixtures/retrieval-independent-cases.ts`：4 份新主题合成资料（含一份与真实答案共享术语的干扰资料）、10 个问题，未参与开发调参。两个数据集在同一命令下分开报告，逐题附带「引用位置」校验：每条证据的编号必须连续、其偏移必须精确切到对应段落原文（与 `checkEvidence` 的跳转前提一致）。该校验只证明引用能落到原文，不代表模型回答语义正确。

2026-10-02 本机结果（小型合成基线，不是对真实学习资料的效果承诺）：

| 指标 | 定义 | 关键词 | 混合 |
| --- | --- | --- | --- |
| Hit@4 | 前 4 片段至少命中一个目标锚点的可回答题比例 | 12/12 | 12/12 |
| Mean Recall@4 | 每题命中目标锚点数/目标总数，对可回答题平均 | 87.5% | 95.83% |
| Mean Target Precision@4 | 返回片段属于标注目标锚点的比例，空结果记 0，对可回答题平均 | 100% | 100% |
| MRR@4 | 第一个正确锚点排名倒数，无命中记 0，再平均 | 1.0 | 1.0 |
| No evidence accuracy | 不可回答/范围不符题返回空证据的比例 | 3/3 | 3/3 |

关键词仍有 `database-multi`、`cache-multi`、`synonym-memory` 三题不完整；混合恢复前后两题，**`cache-multi` 仍只找到一个所需锚点**。最初统一 0.6 阈值的混合成绩与关键词相同；记录失败后加入“关键词支持资料内补充”规则，未改题或删失败。该数据集参与开发，不是独立测试集；Target Precision 只核对标注锚点，不是引用语义准确性，不能写成“真实 RAG 回答准确率 100%”。

独立集 `synthetic-retrieval-v2` 的结果印证了同一局限：关键词 Mean Recall@4 = 87.5%、混合 = 93.75%，两个数据集均有一道多锚点题未找全——独立集的 `ind-symmetric-hash`（“对称加密和哈希函数分别有什么特点？”）只命中一个目标锚点，保留为失败案例。引用位置校验在两个数据集的全部用例上均为 0 错误。这说明多锚点召回仍是关键词与混合检索共同的短板，与是否参与调参无关，属于待改进项而非评测漏洞。

### 阅读一份资料

1. 桌面版进入“资料库”→“导入资料”，选择 PDF 或 Markdown。复制、提取文字时可以取消；已完成的资料保留，失败文件逐个说明原因。
2. 点击“开始阅读”或“继续阅读”。PDF 可用目录、页码、翻页与缩放；Markdown 可点目录跳到标题。两者可切换护眼。
3. 选中同一页或同一章节的原文，点击“复制引用”，得到原文、资料名和页码/标题行号。`study-companion://source/…#…` 当前是来源标识，尚未注册系统链接协议；应用内资料问答的编号引用走受限的保存轮次查询，不依赖系统协议。
4. 看到“阅读位置已保存”后关闭，下次打开自动恢复；首页“最近阅读”也可以继续。阅读位置约 300 毫秒合并保存，异常退出可能丢失最后尚未保存的变更。

**首版限制：**PDF 每份不超过 50 MB、1000 页和 500 万个提取字符；Markdown 不超过 5 MB、必须为 UTF-8；每次最多 20 份，单份解析最长 60 秒。相同内容不重复入库，原件不删除、不修改；导入副本被外部修改时会阻止使用旧引用。解析在独立进程运行，失败不会把该文件标为已导入。扫描件原页可以阅读，但没有 OCR；部分扫描页会单独提示文字不全。密码 PDF 需先解锁。Markdown 原始 HTML、脚本与所有图片不加载，外链不自动打开；跨章节引用、图片阅读、助手/笔记侧栏、引用高亮与导出备份待后续实现。

### 写一份结构化笔记（实现完成，待功能验收）

1. 打开“学习笔记”→“新建笔记”，填写标题和“我的理解、原文依据、待解问题、下一步练习”。可以不关联资料，也可以选一份已导入资料。阅读器的“记笔记”会提出新建关联笔记；有旧草稿时先处理未保存内容。
2. 点击“保存笔记”写入本机 SQLite。切换首页/阅读/聊天时笔记组件保持挂载，当前草稿保留；关闭重开后从列表打开已保存笔记。未保存草稿不写数据库，不承诺强退或界面重载后的恢复。
3. “查看资料”打开关联原件副本，“返回笔记”回到编辑区。原文依据是用户手动记录的 Markdown/引用，**尚未自动核验，也不等于 AI 已验证引用**；下一步练习不会自动创建任务。
4. “导出 Markdown”先保存当前修改，再显示 Windows 保存对话框；导出标题、四个部分、来源名/内容标识及时间，不导出聊天、模型配置或密钥。取消选址不会删除笔记，先前的保存仍保留。只允许 `.md`，禁止覆盖应用数据目录；使用同目录暂存完成后替换目标，失败可能留下暂存副本。
5. 切换/新建笔记前，可选择保存并继续、放弃修改或取消；正常退出时主进程提示未保存内容。删除需明确确认，不能在应用内撤销，建议先导出。遇到版本冲突保留当前编辑，可用“另存为新笔记”保留内容，或明确放弃后重新加载已保存版本。

限制集中于 `src/lib/notes.ts`：标题 120 字符、每部分 20000 字符、最多 1000 份笔记。按标题搜索，暂不含笔记全文检索、Markdown 预览、自动保存、回收站或阅读侧栏。删除笔记也会删除关联反馈，生成中须先停止；Markdown 导出目前只导出笔记正文，不包含反馈历史。功能/异常路径均待独立测试。

### 根据资料获得 AI 笔记反馈（实现完成，待功能验收）

引用编号只能证明对应出处存在，不能证明反馈中的每个判断正确。尚未验证真实模型效果、提示注入抗性、运行时保存/恢复及完整桌面流程，测试对话需独立验收。

4. 记忆标题最多 100 字符、内容 1000 字符、共 500 条。编辑/删除/禁用后旧未发送路线预览失效；切换模型/地址也须重新准备。历史保留当时选择快照，**不再把历史快照加入新请求**。删除不撤回已发给模型的数据，不抹除历史回答/快照及升级备份。
5. 手动保存，页面导航保留草稿；切换记忆/刷新脏稿先确认放弃。关闭应用或重载可能丢失未保存记忆，暂不自动保存或提供关闭拦截。尚无记忆导出、自动合并/提取、跨设备同步。

**测试交接：**[长期记忆完整验收清单](docs/testing/memory-acceptance.md) 按迁移、确认、隐私、双协议/恢复、界面与真实质量列出未执行项目；README 前面的笔记/反馈/路线清单继续有效。新增清单不代表测试已通过。

### 学习项目与每日任务（已实现，待独立功能验收）

1. 打开“学习计划”，选择安排日期，或点击“今天”。列表只显示这一天的真实任务，可按项目筛选，预计分钟是计划值，不是实际学习时间。
2. 创建学习项目，填写标题与目标并明确保存。项目可归档或恢复；本阶段没有项目删除，归档不删除任务，也不自动改变其完成状态。
3. 新建任务，填写标题、详情、安排日期和预计分钟，可关联项目或作为独立任务。可以编辑、改期、转移项目或另存新任务；改期保存成功切换到保存日期查看，另存始终创建待完成任务，不复制旧完成记录。
4. “标记完成”和“重新打开”是独立的手动操作。完成时刻由主进程记录；编辑或改期不会暗中重开，重新打开会清除完成时刻。任务完成不会签到、增加累计学习时间、生成番茄钟记录或推断知识掌握。
5. 归档项目不能接受新任务或新关联；已关联任务仍可编辑、改期、完成、重新打开、解除关联或删除。恢复项目后可以重新新增。
6. 删除前核对已保存任务的完整内容并明确确认；取消不写入，无回收站。版本冲突不覆盖新版本或丢弃编辑稿，可刷新核对或另存新任务。换对象、日期、刷新或关闭编辑区前有脏稿放弃确认，切到其他页面保留草稿；没有自动保存/关闭拦截，关闭或重载可能丢失未保存项目/任务。

**数据与边界：**主库 v9 新增 `study_projects`、`daily_tasks`，只新增表/索引，保留 v1～v8 数据；v8 升级前生成 `before-v9-UUID.sqlite3` 一致性备份，仍在事务中迁移。活动库 v1/派生索引 v2 不变。本轮不打开个人数据库，迁移/恢复仍待验证。项目关联外键禁止级联删除；任务内容保存与完成状态分开，均检查 revision，时间和 UUID 由主进程生成。最多 200 个项目、5000 项任务，标题 120、项目目标 2000、任务详情 4000 字符，预计整数 5～480 分钟；安排日期是合法 `0001-01-01`～`9999-12-31` 本地日历日期，不按 UTC 转换。

**测试交接：**[项目与每日任务验收清单](docs/testing/planning-acceptance.md) 的项目均待执行。当前为单次任务，无重复排程、逾期自动结转、子任务、Agent 自动写入、任务计时或番茄钟；这些能力后续再接。

## 核心学习流程（完整闭环规划中）

**设定目标 → 阅读资料 → 提问求证 → 写出作品 → 获得反馈 → 复盘并安排下一步。**

用户为学习项目设定目标，将资料拆成每日任务；阅读时可以随时向 AI 提问，最终用结构化学习笔记表达自己的理解。助手依据资料给出反馈，并结合学习记录建议下一步。它默认以温柔陪伴的方式鼓励用户，也允许调整回应风格。

### 2. 技术方案与模块边界

以下是首版的实现方向，具体依赖版本在开始编码时以官方文档和锁文件为准：

- **桌面与界面：**Electron、React、TypeScript、Vite。主进程负责文件、SQLite、密钥/模型请求；界面只调用明确桥接。保持沙箱、上下文隔离和 CSP。固定 `utilityProcess` 解析入口为 256 MB V8 堆/60 秒，检索与嵌入入口为 512 MB/5 分钟，均有进度与取消；堆限制不是总内存上限，进程隔离不是文件权限沙箱。
- **阅读：**PDF.js 渲染 PDF 原页并提取可选文字，引用锚点至少保存文档 ID、页码和引用片段；Markdown 按标题层级渲染，引用锚点保存标题位置。导入时将原文件复制到应用数据目录，避免原路径移动后资料失效。
- **本地数据：**主库版本 9 保存设置、资料/阅读、会话/证据、笔记/反馈、学习路线、记忆/选择快照与项目/任务，活动库仍为独立版本 1。升级前备份并事务迁移，v5～v9 迁移待独立验收；派生索引版本 2，重建不覆盖主库。
- **笔记：**`src/lib/notes.ts` 集中四部分模板、限额和导出格式；`note-storage.ts` 只负责校验/SQL/版本冲突，`note-export.ts` 负责路径保护/文件替换；native 对话框只在主进程。笔记关联稳定资料 ID，正文只作为用户作品，不自动授权 Agent 或变成 RAG 证据。保存、删除、导出绑定 revision，冲突不覆盖新版本。
- **笔记反馈：**`note-feedback.ts` 管理主进程预览/版本校验及提示；复用 `SearchService`、`ChatService` 与保存/中断/引用机制。`NoteFeedbackPanel.tsx` 管理预览、发送确认和反馈历史，`ModelAnswer.tsx` 在聊天/反馈共用受限 Markdown 渲染。一个笔记会话关联一份笔记，删除笔记时级联删除反馈；主进程阻止生成中删除。普通聊天不能打开或写入笔记会话。
- **RAG：**页/章节分块保留原文、偏移/锚点。后台 FTS5 与独立 BGE 向量融合后预览；主进程最多缓存 10 份、10 分钟 UUID 预览，界面只发送预览 ID/问题，不能自造证据或系统提示。资料问答不混入普通历史，引用从保存证据核对；嵌入故障只降级检索，不切换聊天服务。模型文件管理、推理适配器、缓存与融合有独立职责，避免把排序/下载逻辑放进 UI。
- **模型适配：**Ollama `/api/tags`、`/api/chat` 与兼容接口 `/models`、`/chat/completions`；NDJSON/SSE 边界由 `chat-stream.ts` 统一，会话/发送确认由 `chat.ts` 管理。`EmbeddingEncoder` 只提供向量/维数/标识/释放，不接触聊天配置或密钥；`embedding-model.ts` 集中版本/清单/输入和排序政策。向量缓存标识含权重 revision、维数、池化、指令、输入政策与运行时版本，换模型不复用旧向量。Windows DPAPI 密钥按服务地址绑定，只在主进程使用，不进库/日志/备份。聊天请求禁重定向；公开模型下载允许官方 CDN 重定向并逐文件校验，不携带聊天密钥。
- **Agent：**`learning-agent.ts` 固定一次检索/一次起草，`learning-input.ts` 共用 IPC/快照校验，`AgentPage.tsx` 管理预览/确认/历史。复用现有请求与出处跳转；`ChatService.send` 的可信上下文仅主进程能传笔记或学习请求/记忆快照。v7 用途隔离三类会话；不执行模型文本命令。
- **记忆：**`memory-storage.ts` 负责范围/来源/版本/SQL，`memory-proposals.ts` 负责有时限的本机预览与单次确认；`src/lib/memories.ts` 集中限额/范围政策。提议根据保存目标起草学习意向，不自动提取评价；主进程确认只收 UUID。路线只用最多 5 条手选记忆，检索前后与发送时核对快照，绑定真实模型配置，不能把本机记忆发远程；历史快照不参与新建议。计划/进度写入仍待开发。
- **项目/任务：**`planning-storage.ts` 负责 v9 新表、日期/文本/关联/revision 校验与参数化 SQL；`src/lib/planning.ts` 集中限额、日期纯校验与空稿。`PlanningPage.tsx` 手动管理项目和指定日期任务，明确保存、脏稿/删除确认与实际返回结果。五个受限 IPC 不接受完成时刻、系统命令或 SQL；状态变化不写活动库、不读密钥/模型。项目只归档/恢复，禁止新增关联到归档项目；Agent 任务写入尚无接口。
- **备份：**导出包含数据库、原始资料及版本信息的本地文件；导入前校验格式与版本，并先保留当前数据，防止误覆盖。密钥不进入备份。

建议的核心数据对象为 `Source`（原始资料）、`Chunk`（带来源锚点的检索片段）、`StudyProject`、`DailyTask`、`FocusSession`、`Note`、`Conversation`、`Memory`。实现时先写数据库迁移和对象约束，再接 UI；不要让界面组件直接拼接 SQL 或持有 API 密钥。

**技术路线决策（2026-09-30）：**原规划使用 Tauri + Rust。环境检查发现需要另行配置 MSVC/C++ 工具后，与用户重新讨论并选择 Electron。理由是集中使用 TypeScript，更便于学习、维护和解释 RAG 项目；接受安装包和内存占用通常较大的代价。仓库保留实际采用的 Electron 方案，不维护第二套桌面实现。后续增加嵌入模型依赖时优先选择预编译方案，并实测其下载体积、中文检索质量与 CPU 性能。

### 4. 横向质量要求

- **数据与隐私：**私人的资料、人格设定、数据库、模型缓存、备份和密钥不得提交 Git。导入资料及云端问答时，界面应清楚显示数据会留在本机还是发送给所选模型服务。
- **可访问性：**阅读、计时、确认弹窗和设置都能用键盘操作；文字对比度、焦点状态和缩放需在三种主题下可用。
- **错误处理：**文件损坏、磁盘空间不足、索引中断、模型不可达、API 限额与备份损坏都应给出可理解的恢复办法；不得把失败静默伪装为成功。
- **测试重点：**优先覆盖数据库迁移与恢复、引用锚点、检索评测、Agent 确认边界、计时中断和备份往返。不要为了覆盖率编写只复述实现的测试。
- **性能：**大文件导入和索引放在后台任务，展示进度并允许取消；阅读和计时界面不能被模型推理阻塞。
- **简历证据：**保留架构图、评测集构建方法、指标定义、失败案例和迭代记录；只展示真实测得的数据。
