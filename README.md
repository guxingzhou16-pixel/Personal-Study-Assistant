私人学习助手是一款以本地数据和个人学习体验为中心的学习软件。它将资料阅读、可追溯的 AI 问答、学习笔记、计划和专注记录连在一起，帮助用户提升注意力和学习效率、理解知识、看见进步，并保持学习动力。第一版以编程与技术学习为主要场景，后续逐步扩展到跨学科资料。

## 本地运行

开发环境为 Windows 10/11、Node.js 24.16 或更新的受支持版本、npm 和 Git。Electron 使用预编译运行时，本阶段开发不要求 Rust 或微软 C++ 编译工具。将来新增原生依赖时须重新评估这个约束。

```powershell
npm ci
npx install-electron --no
npm run desktop:dev
```

首次安装 Electron 需要下载运行时；若下载失败，按 [Electron 官方安装说明](https://www.electronjs.org/docs/latest/tutorial/installation) 配置可用网络或代理，然后重新运行 `npx install-electron --no`。不要将本机代理地址写入项目配置。

开发模式支持界面热更新；修改 `electron/` 后重启开发命令。也可以打开经过构建的桌面版本：

```powershell
npm run desktop:build
npm run desktop:start
```

`npm run dev` 仅提供浏览器界面预览，不能导入本机资料、保存设置、签到或计时，也不能检测模型；这不是展示网站。`desktop:build` 生成界面与桌面程序代码，候选安装包使用下面的独立命令。构建/开发脚本自动从锁定的 PDF.js 依赖复制字库、CMap 与 WASM 到生成目录，阅读不使用 CDN。

### Windows x64 候选构建与安装交接

在 Windows x64、Node >=24.16、npm/Git 环境下，从固定提交的干净克隆构建；保留 `package-lock.json`，构建期间不并行修改源码。首次 Electron 或 NSIS 工具下载需要网络；使用现有预编译运行时，不要求 C++ 编译工具或聊天模型。

```powershell
npm ci
npx install-electron --no
npm run desktop:pack
npm run desktop:dist
```

两个命令均先执行 `desktop:build`，随后只做打包、包内容检查和文件摘要，不启动应用、安装器或功能测试，也不读取学习数据。使用 electron-builder 26.15.3 与 `@electron/asar` 4.3.1；参考 [文件与解包规则](https://www.electron.build/v26/docs/contents/)、[Windows 配置](https://www.electron.build/v26/docs/win/) 与 [NSIS 配置](https://www.electron.build/v26/docs/nsis/)，实际支持字段以已安装版本的 schema 为准。

| 命令/产物 | 范围 |
| --- | --- |
| `npm run desktop:pack` | `release/dir-UUID/win-unpacked/` 完整目录候选；不能只复制其中的 EXE。 |
| `npm run desktop:dist` | `release/nsis-UUID/StudyCompanion-0.1.0-win-x64-setup.exe` NSIS 候选；版本取自 package.json。 |
| `build-info.json` | 开始打包时的 Git HEAD、已追踪改动标志、锁文件 SHA-256、版本/工具/Node/架构/时间；同一份放入包的 resources。记录发生在代码编译之后，不证明此前编译期间源码没有改变。dirty 为 true 不能宣称纯提交构建。 |
| `package-audit.json` | 静态包内容检查：限定顶层、入口、本地 PDF 资源和 Windows 原生文件；`functionalAcceptance` 仍为 pending。 |
| `build-manifest.json`、`SHA256SUMS.txt` | 只有完整构建和检查成功才写；目录模式覆盖 win-unpacked 全部普通文件，含解包 worker、依赖/DLL；NSIS 模式散列整个安装器。哈希用于核对文件，不证明发布者身份或 AI 效果。 |

每次生成新的 UUID 输出目录，失败不会沿用旧成功清单；失败可能留下部分文件，不自动清理旧候选。没有 `build-manifest.json` 与 `SHA256SUMS.txt` 不能当完成产物。`release/` 已忽略，不提交安装器和开发产物。固定依赖使构建过程可重复，时间和 UUID 等元数据使产物不保证逐字节相同。

**使用上述 npm 包装命令构建。** 锁定的 builder 默认会运行临时安装 stub 写出卸载器；`package-desktop.mjs` 在独立打包进程中，仅对本次确切输出/空参数/单次调用改用它已有的 `UninstallerReader` 纯文件提取，成功或失败后还原。未知调用、提取失败或 app-builder-lib 不是 26.15.3 时直接失败，没有执行安装器的回退；不自写安装模板。此处使用已核对的内部接口，升级 builder 必须重新核对模板、提取器与包产物。直接运行 `npx electron-builder` 会绕过这一限制和来源清单。

工具下载不一定读取 Windows 系统代理；网络失败时只为本次下载进程配置已有可用代理，不改仓库地址或关闭 TLS/摘要校验。如果工具缓存解包发生 EXDEV，先检查缓存位置，本轮用临时 `ELECTRON_BUILDER_CACHE` 指向仓库已忽略的 `artifacts/packaging-tool-cache` 后重试，未清空系统缓存或修改个人学习数据。其他机器按实际路径处理，不复制本机代理端口。

`electron-builder.json` 只收 dist、main/preload/三个固定 worker、package.json 与生产依赖，不收仓库文档、测试、第三方下载、私人资料、两库、密钥、备份、检索索引或模型权重。main/preload/界面在 ASAR，三个 ESM worker 与外部依赖在 app.asar.unpacked，主进程通过实际文件位置启动。保留 PDF 字库/CMap/WASM、ONNX/Sharp x64 绑定；不重编译原生依赖、不放宽沙箱/CSP/IPC。文件存在不等于后台进程已运行。

### 从首页组织一次学习（已实现，待独立验收）

1. 首页“今天的小任务”按本机日历日期读取已保存任务，显示待完成/已手动完成的真实数量，前5项优先展示待完成任务。预计分钟与实际专注分开；成功读到空列表才显示未安排，读取失败明确报错并可刷新。
2. 点击“查看全部今日任务”打开当天完整计划并清除旧项目过滤；“查看任务”读取该ID/日期的最新保存版本。计划页有未保存项目或任务时先放弃或取消确认，取消保留草稿；不自动保存或完成任务。
3. 待完成任务的“准备专注”只选中任务、进入专注页，实际记录由目标页重新读取；版本/状态变化按原规则提示。开始时长、计时、结束复盘和手动完成分别明确操作，首页不自动开始、签到或增加学习时间。
4. 六步学习路径分别打开计划、资料库、学习助手、笔记、笔记反馈所在页和专注复盘所在页；已有页面保持挂载，普通导航保留草稿，不强制新建作品或调用模型。编号仅是推荐步骤，不是完成/掌握进度；上方“按自己的节奏”也不是数据评级。
5. 初次无模型可先阅读、写笔记和管理任务；首页提示去设置选择模型。选择后只展示实际已保存名称，不宣称已连接或可生成。“起草学习路线”与“查看学习数据备份”只是页面入口，生成、写入和恢复仍需原有预览/明确操作。

返回首页、显式刷新、窗口获得焦点/恢复可见时重新读取；每30秒只核对本地日期，日期变化才发起查询，不持续轮询数据库。回包或任务点击跨日时重新核对，离页/再次读取/备份暂停后的迟到结果失效；备份非idle时暂停，结束后再读。只读快照不保证点击时任务仍未改变，目标页须重读。

`TodayTasks` 复用现有 `planningOverview`，`HomeStudyFlow` 是纯导航和配置说明，`HomeStudy.css` 复用主题语义变量；App到计划页的内部 `PlanningTarget` 为day/task联合与共用序列，入站优先处理，防旧日期自动刷新竞争。沿用主库v12/活动v1/派生v2/备份format1，无新依赖、迁移或IPC。保留最近阅读/日历以及签到/累计计时两列4:5；实际键盘、缩放与布局仍待验证。[首页学习闭环清单](docs/testing/home-workflow-acceptance.md) 全部待执行，包含无模型完整学习流程与可选AI分支，不把类型/构建当功能验收。

### 和学习助手聊天

1. 在“设置”选择 Ollama 或兼容 OpenAI 接口，填写地址、模型名称，按需保存密钥，再保存设置。本机 Ollama 需先启动并准备聊天模型；模型列表检测成功不保证模型具备聊天能力。
2. 打开“学习助手”，保持“问答方式”为“普通聊天”，输入问题，点击“发送问题”或按 `Ctrl + Enter`。支持普通 Markdown、表格和代码块；不加载模型输出中的图片、HTML 或外链。
3. 模型回应逐段出现，点击“停止生成”立即停止本应用接收并取消请求，保留已有文本；服务端是否立即停止计算或计费由服务实现决定。每次只允许一个回答生成，切换页面/会话后可回来停止。
4. 新建会话可分开讨论不同主题。问题、回答、模型/服务地址、完成状态都存入本机数据库；退出会中断当前生成，重启不自动重新发送。生成中每 500 毫秒保存一次，异常退出可能丢失最后一次保存后的文本；恢复时标记中断，不伪装成完整回答。
5. 远程服务发送前需勾选确认，明确发送目标、近期会话和可能的服务费用。确认绑定地址、模型与接口类型；主进程再次检查目标地址。Ollama 不携带云端密钥，兼容接口只读取其对应地址的密钥。

**当前边界：**普通聊天不检索资料库；最多携带最近 6 轮已完成的普通问答，历史合计不超过 12000 字符（不是 token 上限），资料问答、停止、失败和中断轮次不进入普通上下文。单次问题最多 4000 字符；每会话最多 100 轮（含练习）、最多 500 个会话；历史管理已实现待验收，精确 token 预算仍规划中。普通与资料问答共用输出/网络边界：回答最多 64000 字符，网络响应最多 8 MiB，单行/事件缓冲最多 1048576 字符；连续 120 秒无数据或总时长达到 10 分钟会停止并提示。实际上下文窗口因模型而异，超长请求可能被服务拒绝；不会自动换服务或重试付费请求。

### 基于资料提问（本地混合检索 RAG）

1. 导入资料后，在阅读器点击“问这份资料”，会新建资料问答会话并选中该资料。也可以在“学习助手”切换到“资料问答”，选择一份或全部已导入资料。
2. 写清问题，点击“检索原文”。没有检索模型时使用 FTS5；下载后自动使用本地嵌入与关键词融合，不调用聊天模型或读取 API 密钥。首次建立索引显示进度并可取消；用“重建检索索引”恢复派生缓存，结果包含实际降级说明。
3. 查看“本次检索原文”，展开片段核对资料名、PDF 页码或 Markdown 标题行号。每次最多 4 个片段；扫描或文字不完整的资料会提示限制。更改问题或资料范围后需要重新检索，预览有效期为 10 分钟。
4. 点击“发送问题”，模型只收到系统提示、本次问题和预览中的证据，不包含整份文件、整个资料库或旧问答。远程发送前需勾选确认，确认绑定当前模型配置与本次证据；换问题、预览或模型后重新确认。没有匹配片段时直接保存“无法据此回答”的本地结果，不发请求，也不要求先选择模型。
5. 点击回答中的 `[1]` 等有效引用，或下方“查看原文”，返回实际 PDF 页码/Markdown 标题；点击“返回问答”继续。会话保存引用原文、偏移与锚点，重启后仍可打开；打开前检查副本哈希及引用与保存原文的一致性。未知编号显示为普通文本；缺少/含未知引用编号时提示核查。

**关键词路径：**每页/章节最多 800 个 UTF-16 字符、重叠 120，不拆代理对；中文分词/汉字二元词入 FTS5。BM25 前 40 候选经至少 50% 字面覆盖过滤，去重取最多 4 片段。原有接口和评测基线保留。

**混合路径：**向量窗口 384 字符、重叠 64，标题最多 64 字符，每批 8 个，保留原锚点/偏移。查询加 BGE 指令，长问题分窗口、平均并归一化；分词后超过 512 token 则明确降级，避免默默丢弃长页/问题尾部。向量为归一化 Float32，扫描当前模型缓存；全局语义候选最低余弦 0.6，关键词命中的资料可用 0.5 补充同资料证据。前 40 候选与关键词结果用 RRF（常数 60）融合，重叠片段只贡献一次语义排名，最多 4 片段。启发式参数集中在 `embedding-model.ts`，不证明证据充分；无外部向量服务或语义重排模型。

每次资料问题独立检索，避免只说“继续”或“它”。资料是证据，不授予工具权限；生成模型是否遵循提示、结论是否被支持仍待真实聊天与人工评测。OCR、逐句核验、ANN 大规模索引与引用高亮尚未实现。

### 按资料生成知识卡片与短测验（已实现，待独立验收）

1. 在“学习助手”把问答方式切到“知识卡片”或“短测验”，填写资料中的具体概念（最多1000字符），选择一份或全部资料，点击“检索原文”。复用本地关键词/混合检索，先查看完整原文预览；每次最多4个片段，不发送整个资料库。
2. 核对主题、类型、资料范围和当前模型，远程服务须明确同意发送本次主题/类型和证据。换模型、输入、范围或类型后重新检索与确认；即使模型切回原配置，旧预览也不恢复。取消或换会话时拒收迟到预览，不自动重试。
3. 有证据时一次生成固定3项，不额外调用模型修复格式。每项必须包含非空问题、参考答案和实际证据编号；只有完整结构校验通过才显示可用练习。格式错误、截断、停止或中断保留原始文本与真实未完成状态。空证据只保存本地不足说明，不请求模型或读取密钥。
4. 卡片先显示正面问题，逐张翻面/收起；短测验先写“我的作答”，再展开参考答案、点击出处回原文核查。**作答仅在当前界面保留，不保存、不发给模型，也不进入导出或备份；换会话、重载或关闭可能丢失。** 不自动判对、评分、增加学习时间、签到、任务完成或掌握记录。
5. 请求、原始结果与证据随普通会话保存，可切换/重启读取、改名、删除和导出 Markdown。练习属于资料模式，不进入普通聊天历史或新练习提示；不读取笔记、记忆、路线或计划。重开默认隐藏答案，不记忆翻面状态。

共享 `src/lib/practice.ts` 限定固定3项、每题500字符、答案2000、原始结果10000，严格解析JSON与真实编号；完成/显示/备份共用同一规则。编号存在不代表答案语义正确，参考答案仍需人工对照。主库v12新增可空 `practice_request`，旧行NULL，升级前一致性备份与事务保留旧数据；活动v1/派生v2不变。完整备份当前严格支持12/1，旧11/1文件夹先对应旧版隔离恢复再升级，详见下文。无自动评分、间隔复习、题库/作答历史或练习任务提议。

模型仓库固定 revision `75c43b069aac4d136ba6bc1122f995fedcfd2781`，5 文件逐项核对大小/SHA-256，全部校验后替换副本。下载最多 15 分钟，不续传；正常取消/失败清理暂存，保留已有副本，异常退出可能遗留暂存。推理禁止远程模型读取，CPU 最多 4 线程；检索进程 512 MB V8 堆、5 分钟超时，不代表总内存上限。本机 ONNX Runtime 的 Windows x64 原生目录约 64 MiB，Transformers.js 约 9.4 MiB，另有其他依赖；安装包大小与资源裁剪未验证。每次检索重新加载模型，评测的热查询耗时不等于桌面操作耗时。

固定数据集 `synthetic-retrieval-v1` 在 `tests/fixtures/retrieval-cases.ts`：6 份合成资料、15 个问题（9 个直接概念、2 个跨段落、1 个换说法、3 个不可回答/范围不符）。直接构建临时来源数据库，不读取个人资料；关键词评测不调用模型，混合评测只调用真实本地嵌入，不调用聊天/云 API。文件解析另有桌面测试。

报告为已忽略的 `artifacts/retrieval-evaluation.json` 和 `artifacts/hybrid-retrieval-evaluation.json`，保留逐题期望/实际锚点、失败项、配置/模型标识、硬件和耗时。退出码 0 不代表每题完整命中；混合评测发生嵌入降级时返回非零，不把关键词成绩冒充混合成绩。缺少权重时要求先下载，评测与真实模型桌面验证不自动联网。普通 `test:e2e` 与真实权重的 `test:embedding` 是不同门禁。

独立数据集 `synthetic-retrieval-v2` 在 `tests/fixtures/retrieval-independent-cases.ts`：4 份新主题合成资料（含一份与真实答案共享术语的干扰资料）、10 个问题，未参与开发调参。两个数据集在同一命令下分开报告，逐题附带「引用位置」校验：每条证据的编号必须连续、其偏移必须精确切到对应段落原文（与 `checkEvidence` 的跳转前提一致）。该校验只证明引用能落到原文，不代表模型回答语义正确。

2026-10-02 本机结果（小型合成基线，不是对真实学习资料的效果承诺）：

| 指标 | 定义 | 关键词 | 混合 |
| --- | --- | --- | --- |
| Hit@4 | 前 4 片段至少命中一个目标锚点的可回答题比例 | 12/12 | 12/12 |
| Mean Recall@4 | 每题命中目标锚点数/目标总数，对可回答题平均 | 87.5% | 95.83% |
| Mean Target Precision@4 | 返回片段属于标注目标锚点的比例，空结果记 0，对可回答题平均 | 100% | 100% |
| MRR@4 | 第一个正确锚点排名倒数，无命中记 0，再平均 | 1.0 | 1.0 |
| No evidence accuracy | 不可回答/范围不符题返回空证据的比例 | 3/3 | 3/3 |

关键词仍有 `database-multi`、`cache-multi`、`synonym-memory` 三题不完整；混合恢复前后两题，**`cache-multi` 仍只找到一个所需锚点**。最初统一 0.6 阈值的混合成绩与关键词相同；记录失败后加入“关键词支持资料内补充”规则，未改题或删失败。该数据集参与开发，不是独立测试集；Target Precision 只核对标注锚点，不是引用语义准确性，不能写成“真实 RAG 回答准确率 100%”。

独立集 `synthetic-retrieval-v2` 的结果印证了同一局限：关键词 Mean Recall@4 = 87.5%、混合 = 93.75%，两个数据集均有一道多锚点题未找全——独立集的 `ind-symmetric-hash`（“对称加密和哈希函数分别有什么特点？”）只命中一个目标锚点，保留为失败案例。引用位置校验在两个数据集的全部用例上均为 0 错误。这说明多锚点召回仍是关键词与混合检索共同的短板，与是否参与调参无关，属于待改进项而非评测漏洞。

### 阅读一份资料

1. 桌面版进入“资料库”→“导入资料”，选择 PDF 或 Markdown。复制、提取文字时可以取消；已完成的资料保留，失败文件逐个说明原因。

3. 选中同一页或同一章节的原文，点击“复制引用”，得到原文、资料名和页码/标题行号。`study-companion://source/…#…` 当前是来源标识，尚未注册系统链接协议；应用内资料问答的编号引用走受限的保存轮次查询，不依赖系统协议。
4. 看到“阅读位置已保存”后关闭，下次打开自动恢复；首页“最近阅读”也可以继续。阅读位置约 300 毫秒合并保存，异常退出可能丢失最后尚未保存的变更。

### 完整学习数据备份与恢复（已实现，待独立功能验收）

1. 先保存需要保留的编辑内容，暂停首页累计计时，结束番茄钟（暂停的专注也须结束），并完成或取消导入、检索、生成和模型下载。备份处理期间其他学习操作暂时锁定，状态与取消入口仍可用。

3. 恢复时点击“选择备份并预览”，选择包含 `manifest.json` 的那一层。程序先在本机隔离目录复制并检查大小、SHA-256、数据库结构、记录及关联，展示备份时间、体积，以及资料、笔记、会话、问答/路线/练习、记忆、项目、任务、专注和日历记录九类数量。

5. 确认后再次校验暂存副本，写入待恢复记录并重启。启动时再次核对、打开新数据库成功后才切换学习位置；旧学习目录和准确的旧位置记录保留。设置页显示恢复时间、当前目录和保留目录。取消或切换前失败不改变当前学习数据。

**备份包含什么：**主库中的设置、资料/阅读位置、聊天/练习及出处、笔记/反馈、学习路线、记忆、项目/任务及来源、专注/复盘；活动库中的签到与按日累计时长；每份导入资料的完整原件副本。只包含已经保存的内容，不含未保存草稿或未确认提议。

```text
拾知备份-时间-标识/
  manifest.json
  study-companion.sqlite3
  study-activity.sqlite3
  sources/                 与数据库对应的 PDF/Markdown 哈希副本
```

导出使用 [Node.js SQLite backup API](https://nodejs.org/api/sqlite.html#sqlitebackupsource-db-path-options) 生成保留原记录与 rowid 的一致性副本，两个数据库在业务写入暂停期间顺序快照；不直接复制正在使用的 WAL 数据库。独立 `utilityProcess` 执行校验与逐文件流式复制，256 MB V8 堆限制、三十分钟超时（堆限制不是总内存上限）。清单最后写入，处理进程退出后才完成文件夹；失败或取消只清理本次新建目录，清理失败会提示，不删原备份或当前学习目录。

**边界与隐私：**

- 备份格式为版本 1，只恢复当前主库 v12 / 活动库 v1 的完整备份，精确匹配现行schema及练习快照。**旧11/1文件夹备份本版拒绝**：用对应旧版在隔离环境恢复，再由新版本迁移该数据目录；不能改清单数字冒充兼容。直接打开旧学习目录可前向迁移，文件夹恢复不自动迁移旧备份。旧格式、新版本、单独的迁移前数据库备份都不是此功能支持的恢复包，不手改版本号绕过校验。
- 每个数据库最多 2 GiB、最多 10000 份资料、总文件大小最多 50 GiB、清单最多 3 MiB；单份 PDF/Markdown 仍受原导入限额约束。拒绝多余文件、路径越界、目录/文件链接、硬链接、摘要或数量不符、异常结构/触发器、无效记录或关联。SHA-256 说明副本完整性，不证明来源可信或 AI 回答正确。
- **备份未加密**，包含个人学习内容与历史记忆，只保存在可信位置。API 密钥及密文、本机模型、派生索引、旧备份、缓存和日志不导出；密钥和模型仍留在应用根目录。换机器后自行配置密钥与下载检索模型，索引按需重建，恢复不自动请求模型。
- 预览绑定已复制的隔离副本；原备份后来改动不会改变预览内容，暂存副本改变则拒绝确认。最终写入及等待重启阶段不能取消；确认应答丢失时先“重新读取状态”，不要重复提交。自动重启失败时按提示手动退出重开，待恢复记录仍保留。

#### 恢复后的目录与手动回退

应用数据根目录仍为 `%APPDATA%\StudyCompanion\`，开发隔离目录仍用原环境变量。恢复后布局为：

```text
active-learning.json       当前学习目录及恢复时间；没有此文件时使用根目录
pending-restore.json       已确认、等待启动处理的记录，不等于恢复完成回执
before-restore-UUID.json   此次恢复前的准确 active 记录；首次恢复前为 null
learning-restores/UUID/    新学习数据；切换后继续在此保存，不搬动旧库
credentials.enc.json      仍在根目录，未导出
embedding-models/          仍在根目录，未导出
```

切换前的校验、开库或位置写入失败时，程序保留旧数据并报告；等待记录改名保存，避免下一次自动重复。若当前位置记录损坏或指向的数据库缺失，则拒绝创建空库代替。已完成切换但等待记录清理失败时说明“已恢复、清理失败”，不误报仍在使用旧数据。

需要回退时，先**完全退出应用**，用资源管理器把整个应用数据根目录复制到可信的外部位置（这份应急副本含机器绑定的密钥密文，不能当作可分享的导出备份）。检查设置页此前显示的保留目录仍有两个数据库和 `sources/`，再按当前 `active-learning.json` 的 UUID 找到对应 `before-restore-UUID.json`：

1. 文件内容为 `null`：将当前 `active-learning.json` 改名留存，下一次使用原根目录。
2. 文件内容为旧位置对象：将当前 active 文件改名留存，将这份准确旧记录复制为 `active-learning.json`，不要自行编造 UUID 或改数据库版本。
3. 若还有 `pending-restore.json`，也改名留存，防止下一次继续应用等待恢复。不要移动或删除任何学习库或资料文件。
4. 重新启动，核对实际记录与设置页当前目录。不要在应用运行时处理这些文件；回退也会保留恢复后新增的数据目录，记录不会自动合并。

本轮仅完成主线实现、类型/生产构建与静态审查，没有启动应用、读取个人数据库或执行功能测试。[备份与恢复独立验收清单](docs/testing/backup-acceptance.md) 全部待执行，优先在临时目录验证往返、故障与回退，再使用真实个人数据。

## 核心学习流程（入口已接入，完整闭环待验收）

**设定目标 → 阅读资料 → 提问求证 → 写出作品 → 获得反馈 → 复盘并安排下一步。**

首版仅支持 Windows，不要求账号或跨设备同步。资料、阅读位置、偏好、聊天会话、签到和学习时间已保存在本机；笔记/反馈/路线/记忆、项目/任务、专注及练习请求/结果已接入主库，待独立验收；笔记可导出 Markdown。完整学习数据的手动文件夹备份、校验预览、确认重启恢复已实现待验收，旧数据保留，备份不包含 API 密钥。桌面技术为 Electron、React、TypeScript、Vite 与 SQLite，阅读器采用 PDF.js 与安全 Markdown 渲染。

### 2. 技术方案与模块边界

以下是首版的实现方向，具体依赖版本在开始编码时以官方文档和锁文件为准：

- **桌面与界面：**Electron、React、TypeScript、Vite。主进程负责文件、SQLite、密钥/模型请求；界面只调用明确桥接。保持沙箱、上下文隔离和 CSP。固定 `utilityProcess` 解析入口为 256 MB V8 堆/60 秒，检索与嵌入入口为 512 MB/5 分钟，均有进度与取消；堆限制不是总内存上限，进程隔离不是文件权限沙箱。
- **首页闭环：**`TodayTasks`只读现有planningOverview，按本机日期/恢复/手动刷新读取，最多展示5项与完整数量；取消effect拒迟到快照，备份期间暂停。`HomeStudyFlow`只导航、显示实际保存模型，不检测/请求模型。App把day/task导航目标传PlanningPage，复用脏稿确认与实际读取；新目标优先于旧日期自动刷新。步骤和统计不写完成/签到/时长或推断掌握，无新数据结构/IPC。
- **主题/偏好：**已有 `app_settings.value` JSON新增受限theme字段，不新增表/IPC或存第二份localStorage。旧记录缺字段默认modern、非法现值拒绝；`themes.ts`共用选项/校验，`themes.css`集中配色，App依据实际偏好设置根属性。语义变量回退保留默认颜色，原有布局与资料正文/护眼不复制或改写；视觉不影响模型配置/回应风格/确认权限。
- **Windows 分发：**`electron-builder.json` 集中 x64/ASAR/原生资源与当前用户 NSIS 配置；`package-desktop.mjs` 管唯一输出、来源与全文件/安装器摘要，`verify-package.mjs` 只检查包内容。正式 worker 使用 app.asar.unpacked 实体目录，开发模式保留原位置；appId、appName 与 APPDATA 约定保持稳定。构建不启动应用、不运行功能测试、不创建 Release；安装验收独立隔离，源代码构建与完整打包命令分开。
- **阅读：**PDF.js 渲染 PDF 原页并提取可选文字，引用锚点至少保存文档 ID、页码和引用片段；Markdown 按标题层级渲染，引用锚点保存标题位置。导入时将原文件复制到应用数据目录，避免原路径移动后资料失效。
- **本地数据：**主库版本 12 保存设置、资料/阅读、会话/证据、笔记/反馈、学习路线、记忆/选择快照与项目/任务及任务来源、专注和练习请求，活动库仍为独立版本 1。升级前备份并事务迁移，v5～v12 迁移待独立验收；派生索引版本 2，重建不覆盖主库。
- **笔记：**`src/lib/notes.ts` 集中四部分模板、限额和导出格式；`note-storage.ts` 只负责校验/SQL/版本冲突，`note-export.ts` 负责路径保护/文件替换；native 对话框只在主进程。笔记关联稳定资料 ID，正文只作为用户作品，不自动授权 Agent 或变成 RAG 证据。保存、删除、导出绑定 revision，冲突不覆盖新版本。
- **笔记反馈：**`note-feedback.ts` 管理主进程预览/版本校验及提示；复用 `SearchService`、`ChatService` 与保存/中断/引用机制。`NoteFeedbackPanel.tsx` 管理预览、发送确认和反馈历史，`ModelAnswer.tsx` 在聊天/反馈共用受限 Markdown 渲染。一个笔记会话关联一份笔记，删除笔记时级联删除反馈；主进程阻止生成中删除。普通聊天不能打开或写入笔记会话。
- **RAG：**页/章节分块保留原文、偏移/锚点。后台 FTS5 与独立 BGE 向量融合后预览；主进程最多缓存 10 份、10 分钟 UUID 预览，界面只发送预览 ID/问题，不能自造证据或系统提示。资料问答不混入普通历史，引用从保存证据核对；嵌入故障只降级检索，不切换聊天服务。模型文件管理、推理适配器、缓存与融合有独立职责，避免把排序/下载逻辑放进 UI。
- **模型适配：**Ollama `/api/tags`、`/api/chat` 与兼容接口 `/models`、`/chat/completions`；NDJSON/SSE 边界由 `chat-stream.ts` 统一，会话/发送确认由 `chat.ts` 管理。`EmbeddingEncoder` 只提供向量/维数/标识/释放，不接触聊天配置或密钥；`embedding-model.ts` 集中版本/清单/输入和排序政策。向量缓存标识含权重 revision、维数、池化、指令、输入政策与运行时版本，换模型不复用旧向量。Windows DPAPI 密钥按服务地址绑定，只在主进程使用，不进库/日志/备份。聊天请求禁重定向；公开模型下载允许官方 CDN 重定向并逐文件校验，不携带聊天密钥。
- **Agent：**`learning-agent.ts` 固定一次检索/一次起草，`learning-input.ts` 共用 IPC/快照校验，`AgentPage.tsx` 管理预览/确认/历史。复用现有请求与出处跳转；`ChatService.send` 的可信上下文仅主进程能传笔记、学习请求/记忆快照或练习请求。v7 用途隔离三类会话；不执行模型文本命令。
- **练习：**`practice.ts` 管v12迁移、请求校验、不可改写的预览/配置缓存与专用提示，沿用SearchService/ChatService；`src/lib/practice.ts` 在终态/显示/备份统一严格三项结构及引用校验。`PracticeResult`只纯文本翻面/本地作答，ChatPage四种模式共享一个网络管线。练习存在普通会话sources轮次，以practiceRequest识别且不进普通上下文；不重建purpose约束、不自动评分或写进度。
- **记忆：**`memory-storage.ts` 负责范围/来源/版本/SQL，`memory-proposals.ts` 负责有时限的本机预览与单次确认；`src/lib/memories.ts` 集中限额/范围政策。提议根据保存目标起草学习意向，不自动提取评价；主进程确认只收 UUID。路线只用最多 5 条手选记忆，检索前后与发送时核对快照，绑定真实模型配置，不能把本机记忆发远程；历史快照不参与新建议。任务新增走独立确认，已有进度由用户管理。
- **项目/任务：**`planning-storage.ts` 负责 v9新表/v10来源迁移、输入/恢复/关联/revision校验、参数化SQL与确认创建事务；`src/lib/planning.ts` 集中限额、日期纯校验与空稿。`PlanningPage.tsx` 手动管理，自动列表刷新保留草稿，打开目标任务重新读取并尊重脏稿确认。五个手动IPC不接受来源/状态时刻/SQL，项目只归档/恢复；状态不写活动库、不读密钥/模型，另存新任务来源manual。
- **任务提议：**`task-proposals.ts` 从主库读取真实路线，主进程缓存确切单任务草稿、来源revision与完整项目快照，10份/10分钟；`TaskProposalPanel` 管理编辑失效/最终预览/确认/拒绝及实际结果。确认只收UUID，复核来源/项目后在事务内新增todo，成功才消费预览；不执行模型工具或自动改变已有进度。来源标识不级联删除任务，不是整份回答快照。App传递刷新通知及受控任务/来源导航，无新增模型请求。
- **备份：**`backup.ts` 管维护状态、原生选址/确认、十分钟预览与重启，`backup-runner.ts` 管固定进程/取消/等待退出，`backup-files.ts` 管两库快照/流式复制/清单/摘要，`backup-data.ts` 管结构/记录/关联校验，`data-location.ts` 管隔离目录/准确旧位置/原子切换。`backup-worker.ts` 为固定独立入口，`BackupPanel` 与 `useBackupState` 管实际状态和处理弹窗；界面不给路径、SQL或数据库正文。当前只支持主库v12/活动v1，恢复后学习目录与密钥/模型根目录分开，不改变数据库结构。仅确认后写等待记录，启动再校验开库成功才切换，旧目录保留；完整功能待独立验收。

- **专注：**focus-storage.ts 管v11表、运行时恢复校验、条件事务与专注历史；focus.ts 的FocusTracker管单轮单调计时/暂停/计满/中断/故障冻结，不写活动库或任务进度。每秒elapsed落盘不增控制revision，状态/复盘变更才递增；overview.version拒绝迟到快照。FocusPage保持挂载，控制/复盘失败后明确核对记录，不自动重发。

建议的核心数据对象为 `Source`（原始资料）、`Chunk`（带来源锚点的检索片段）、`StudyProject`、`DailyTask`、`FocusSession`、`Note`、`Conversation`、`Memory`。实现时先写数据库迁移和对象约束，再接 UI；不要让界面组件直接拼接 SQL 或持有 API 密钥。

**技术路线决策（2026-09-30）：**原规划使用 Tauri + Rust。环境检查发现需要另行配置 MSVC/C++ 工具后，与用户重新讨论并选择 Electron。理由是集中使用 TypeScript，更便于学习、维护和解释 RAG 项目；接受安装包和内存占用通常较大的代价。仓库保留实际采用的 Electron 方案，不维护第二套桌面实现。后续增加嵌入模型依赖时优先选择预编译方案，并实测其下载体积、中文检索质量与 CPU 性能。

### 4. 横向质量要求

- **数据与隐私：**私人的资料、人格设定、数据库、模型缓存、备份和密钥不得提交 Git。导入资料及云端问答时，界面应清楚显示数据会留在本机还是发送给所选模型服务。
- **可访问性：**阅读、计时、确认弹窗和设置都能用键盘操作；文字对比度、焦点状态和缩放需在三种主题下可用。
- **错误处理：**文件损坏、磁盘空间不足、索引中断、模型不可达、API 限额与备份损坏都应给出可理解的恢复办法；不得把失败静默伪装为成功。
- **测试重点：**优先覆盖数据库迁移与恢复、引用锚点、检索评测、Agent 确认边界、计时中断和备份往返。不要为了覆盖率编写只复述实现的测试。
- **性能：**大文件导入和索引放在后台任务，展示进度并允许取消；阅读和计时界面不能被模型推理阻塞。
- **简历证据：**保留架构图、评测集构建方法、指标定义、失败案例和迭代记录；只展示真实测得的数据。
