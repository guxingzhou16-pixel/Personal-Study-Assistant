# 私人学习助手（Study Companion）

> **项目状态：阶段 0 的 Windows 桌面骨架已完成，模型连接配置与检测已实现。** 可以打开学习工作台、保存偏好和检测模型服务；资料导入、阅读器、聊天生成、RAG 与 Agent 仍在规划中。展示网站留到软件完成后建设。

私人学习助手是一款以本地数据和个人学习体验为中心的学习软件。它将资料阅读、可追溯的 AI 问答、学习笔记、计划和专注记录连在一起，帮助用户提升注意力和学习效率、理解知识、看见进步，并保持学习动力。第一版以编程与技术学习为主要场景，后续逐步扩展到跨学科资料。

## 已实现的功能

| 功能 | 当前可用范围 |
| --- | --- |
| Windows 桌面工作台 | 首页、空资料库、设置和基础导航；规划中的入口会明确标注，不展示虚构学习记录。 |
| 学习偏好 | 称呼、每日目标、回应风格存入 SQLite；关闭重开后恢复。回应风格会在聊天接入后传给模型。 |
| 模型连接配置 | Ollama 与兼容 OpenAI 的接口分别保存地址、模型名；检测服务、返回模型列表，区分鉴权、地址、限额、超时及响应格式错误。 |
| 密钥管理 | 使用 Electron `safeStorage` 调用 Windows DPAPI 加密，密文单独保存在本机；可删除，按服务地址绑定，不写入学习数据库或 Git。 |
| 验证与构建 | TypeScript 类型检查、生产构建、17 项核心测试、2 项真实 Electron 窗口端到端测试；已配置 Windows GitHub Actions，远端执行结果另行记录。 |

## 本地运行

开发环境为 Windows 10/11、Node.js 24.16 或更新的受支持版本、npm 和 Git。Electron 使用预编译运行时，本阶段开发不要求 Rust 或微软 C++ 编译工具。将来新增原生依赖时须重新评估这个约束。

```powershell
npm ci
npx install-electron --no
npm run desktop:dev
```

首次安装 Electron 需要下载运行时；若下载失败，按 [Electron 官方安装说明](https://www.electronjs.org/docs/latest/tutorial/installation) 配置可用网络或代理，然后重新运行 `npx install-electron --no`。不要将本机代理地址写入项目配置。

开发模式支持界面热更新；修改 `electron/` 后重启开发命令。也可以打开经过构建的桌面版本：

```powershell
npm run desktop:build
npm run desktop:start
```

`npm run dev` 仅提供浏览器界面预览，不能保存本地设置或检测模型；这不是展示网站。当前尚未生成可分发的安装包，`desktop:build` 生成的是界面与桌面程序代码。

验证命令：

```powershell
npm run format:check
npm test
npm run test:e2e
```

端到端测试会实际启动、关闭、重开 Electron，使用临时数据目录，不访问个人资料、不消耗 API 额度。测试验证导航、偏好恢复、两种模型接口、鉴权错误、Windows 密钥加密与删除、界面隔离及最小窗口宽度。

默认数据目录为 `%APPDATA%\StudyCompanion\`：`study-companion.sqlite3` 保存学习设置，`sources/` 预留给导入原文件，`credentials.enc.json` 保存密钥密文。密文与 Windows 账户绑定，不能作为跨机器密钥备份；后续导出功能必须排除它。首版不需要注册账户。

## 核心学习流程（规划中）

**设定目标 → 阅读资料 → 提问求证 → 写出作品 → 获得反馈 → 复盘并安排下一步。**

用户为学习项目设定目标，将资料拆成每日任务；阅读时可以随时向 AI 提问，最终用结构化学习笔记表达自己的理解。助手依据资料给出反馈，并结合学习记录建议下一步。它默认以温柔陪伴的方式鼓励用户，也允许调整回应风格。

## 主要功能与开发范围

### 资料阅读（规划中）

- 首版导入 PDF 和 Markdown。PDF 保留原始版式，提供目录、缩放、护眼、选中文本提问和引用跳转；Markdown 提供适合长时间阅读的排版。
- 阅读区搭配可收起的侧边助手和笔记区。首版优先处理可提取文字的 PDF；扫描件 OCR 和更多文件格式留待后续。

### 可追溯的 RAG 问答（规划中）

- 从已导入资料中检索证据，再生成回答；引用定位到 PDF 页码或 Markdown 标题。资料不足时明确说明，不编造出处。
- 结合全文检索与本地向量检索，并通过固定问答集记录检索命中率、引用准确性和失败案例，让 RAG 效果可验证、可改进。

### 小型学习 Agent 与长期记忆（规划中）

- 根据目标和资料建议学习步骤，辅助检索、解释、追问、起草笔记以及安排每日任务。
- 新增计划、更新进度或写入长期记忆前由用户确认。学习轨迹与个人偏好都可以查看、编辑和删除。
- 结构化学习笔记是默认作品。AI 给出有资料依据的已掌握点、知识缺口和改进建议；知识卡片与短测验按需生成。

### 模型接入（配置与检测已实现，聊天与嵌入规划中）

- 本地模型支持 Ollama；云端模型支持用户自行填写兼容 OpenAI API 的地址、密钥和模型名。本地与云端模型可平等选择。
- 资料检索所需的本地嵌入模型独立于聊天模型。用户无需因为选择云端聊天而安装 Ollama；嵌入模型不可用时保留关键词检索。
- 云端 API 费用由使用者自行承担，软件不内置收费模型服务。

### 计划、专注与个性化（偏好保存已实现，其余规划中）

- 以学习项目和每日任务组织计划；番茄钟关联任务，结束后支持简短复盘和打卡。
- 默认使用清爽现代界面，并提供安静书房、活泼游戏化主题；回应风格可在温柔陪伴、游戏化成长和高效教练之间切换。

首版仅支持 Windows，不要求账号或跨设备同步。偏好已保存在本机；资料、笔记、学习记录以及完整导入导出仍在规划中，备份不包含 API 密钥。桌面技术已确定为 Electron、React、TypeScript、Vite 与 SQLite，后续阅读器使用 PDF.js。

### 2. 技术方案与模块边界

以下是首版的实现方向，具体依赖版本在开始编码时以官方文档和锁文件为准：

- **桌面与界面：**Electron 承载 Windows 应用；React、TypeScript、Vite 构建界面。Electron 主进程的 Node.js 负责文件、SQLite、密钥加密和模型请求；界面通过预加载脚本提供的少量明确接口调用这些能力。已启用进程沙箱、上下文隔离和 CSP，界面不拥有 Node.js 或任意文件访问能力。长耗时解析与索引以后放入工作线程，避免阻塞主进程。
- **阅读：**PDF.js 渲染 PDF 原页并提取可选文字，引用锚点至少保存文档 ID、页码和引用片段；Markdown 按标题层级渲染，引用锚点保存标题位置。导入时将原文件复制到应用数据目录，避免原路径移动后资料失效。
- **本地数据：**使用 Electron 内置 Node.js 的 `node:sqlite`，避免额外编译原生数据库依赖。当前迁移版本 1 只包含设置表；后续逐步增加资料、分块、会话、笔记、项目、任务、专注记录与记忆。原文件和模型文件存应用数据目录。全文检索使用 SQLite FTS5，启动时已探测其可用性。个人规模优先，不引入需要单独部署的数据库或向量服务。
- **RAG：**按页或标题结构切分资料并保留来源位置；本地多语言嵌入模型生成向量，与全文检索结果融合后交给聊天模型。回答只能引用实际取回的片段；证据不足时说明限制。嵌入模型首次使用时下载并缓存，下载失败时仍可进行全文检索和普通阅读。
- **模型适配：**当前通过 Ollama `/api/tags` 和兼容 OpenAI `/models` 检测服务与模型列表；后续增加统一聊天、流式输出和错误报告契约。聊天模型与嵌入模型配置分离。云端密钥由 Windows DPAPI 加密，密文与学习数据库分开，不进入仓库、日志或备份；读取密钥只发生在主进程，界面只获知是否存在。密钥绑定规范化的服务基础地址，修改地址后不会把旧地址的密钥发给新服务。远程地址要求 HTTPS，本机回环地址支持 HTTP；模型请求禁止跟随重定向，设置超时并限制响应大小。
- **Agent：**采用受控的步骤流程，而非无限循环自主执行。工具仅包括资料检索、生成学习步骤草稿、笔记反馈、任务建议和记忆提议；每次写入计划、进度或记忆时显示变更预览并等待确认。
- **备份：**导出包含数据库、原始资料及版本信息的本地文件；导入前校验格式与版本，并先保留当前数据，防止误覆盖。密钥不进入备份。

建议的核心数据对象为 `Source`（原始资料）、`Chunk`（带来源锚点的检索片段）、`StudyProject`、`DailyTask`、`FocusSession`、`Note`、`Conversation`、`Memory`。实现时先写数据库迁移和对象约束，再接 UI；不要让界面组件直接拼接 SQL 或持有 API 密钥。

**技术路线决策（2026-09-30）：**原规划使用 Tauri + Rust。环境检查发现需要另行配置 MSVC/C++ 工具后，与用户重新讨论并选择 Electron。理由是集中使用 TypeScript，更便于学习、维护和解释 RAG 项目；接受安装包和内存占用通常较大的代价。仓库保留实际采用的 Electron 方案，不维护第二套桌面实现。后续增加嵌入模型依赖时优先选择预编译方案，并实测其下载体积、中文检索质量与 CPU 性能。

当前目录与职责：

```text
src/                    React 工作台与设置界面
  lib/types.ts          跨进程类型与默认设置
  lib/desktop.ts        界面调用桌面能力的入口
electron/
  main.ts               窗口、权限、IPC 与本地生命周期
  preload.ts            仅暴露明确的桌面操作
  core/storage.ts       SQLite 迁移与设置保存
  core/credentials.ts   按地址管理系统加密的密钥密文
  core/models.ts        模型列表检测、超时和错误映射
  core/*.test.ts        本地数据与模型异常路径测试
scripts/                桌面构建与开发启动
tests/desktop.spec.ts   真实 Electron 端到端测试
.github/workflows/      Windows 构建与验证流程
```
