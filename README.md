# 私人学习助手（Study Companion）

> **项目状态：阶段 0、阶段 1 基础阅读与阶段 2 的流式聊天已完成。** 已实现 Windows 桌面工作台、模型连接配置、首页月历、每日签到、学习计时、PDF/Markdown 导入阅读，以及可停止、可恢复的普通聊天。资料检索、可点击 AI 引用、RAG 与 Agent 仍在规划中。展示网站留到软件完成后建设。

私人学习助手是一款以本地数据和个人学习体验为中心的学习软件。它将资料阅读、可追溯的 AI 问答、学习笔记、计划和专注记录连在一起，帮助用户提升注意力和学习效率、理解知识、看见进步，并保持学习动力。第一版以编程与技术学习为主要场景，后续逐步扩展到跨学科资料。

## 本地运行

开发环境为 Windows 10/11、Node.js 24.16 或更新的受支持版本、npm 和 Git。Electron 使用预编译运行时，本阶段开发不要求 Rust 或微软 C++ 编译工具。将来新增原生依赖时须重新评估这个约束。

```powershell
npm ci
npx install-electron --no
npm run desktop:dev
```

首次安装 Electron 需要下载运行时；若下载失败，按 [Electron 官方安装说明](https://www.electronjs.org/docs/latest/tutorial/installation) 配置可用网络或代理，然后重新运行 `npx install-electron --no`。不要将本机代理地址写入项目配置。

开发模式支持界面热更新；修改 `electron/` 后重启开发命令。也可以打开经过构建的桌面版本：

```powershell
npm run desktop:build
npm run desktop:start
```

`npm run dev` 仅提供浏览器界面预览，不能导入本机资料、保存设置、签到或计时，也不能检测模型；这不是展示网站。当前尚未生成可分发的安装包，`desktop:build` 生成的是界面与桌面程序代码。构建/开发脚本自动从锁定的 PDF.js 依赖复制字库、CMap 与 WASM 到生成目录，阅读不使用 CDN。

验证命令：

```powershell

npm run test:e2e
```

端到端测试会实际启动、关闭、重开 Electron，使用临时数据目录，不访问个人资料、不消耗 API 额度。测试验证导航、偏好恢复、两种模型接口、鉴权错误、Windows 密钥加密与删除、界面隔离及最小窗口宽度。

### 和学习助手聊天

1. 在“设置”选择 Ollama 或兼容 OpenAI 接口，填写地址、模型名称，按需保存密钥，再保存设置。本机 Ollama 需先启动并准备聊天模型；模型列表检测成功不保证模型具备聊天能力。
2. 打开“学习助手”，输入问题，点击“发送问题”或按 `Ctrl + Enter`。支持普通 Markdown、表格和代码块；不加载模型输出中的图片、HTML 或外链。
3. 模型回应逐段出现，点击“停止生成”立即停止本应用接收并取消请求，保留已有文本；服务端是否立即停止计算或计费由服务实现决定。每次只允许一个回答生成，切换页面/会话后可回来停止。
4. 新建会话可分开讨论不同主题。问题、回答、模型/服务地址、完成状态都存入本机数据库；退出会中断当前生成，重启不自动重新发送。生成中每 500 毫秒保存一次，异常退出可能丢失最后一次保存后的文本；恢复时标记中断，不伪装成完整回答。
5. 远程服务发送前需勾选确认，明确发送目标、近期会话和可能的服务费用。确认绑定地址、模型与接口类型；主进程再次检查目标地址。Ollama 不携带云端密钥，兼容接口只读取其对应地址的密钥。

**当前边界：**这是普通聊天，尚无资料检索和可点击 AI 引用。单次问题最多 4000 字符；最多携带最近 6 轮已完成的问答，历史合计不超过 12000 字符（不是 token 上限），停止、失败和中断的回答不进入上下文。每会话最多 100 次提问、最多 500 个会话；会话删除、重命名、导出和精确 token 预算待后续实现。单次回答上限 64000 字符，网络响应总量最多 8 MiB，单行及事件数据缓冲上限 1048576 字符；连续 120 秒无网络数据或总时长达到 10 分钟会停止并提示。上下文窗口因模型而异，过长请求可能被服务拒绝；不会自动换用另一服务或重试付费请求。

### 阅读一份资料

1. 桌面版进入“资料库”→“导入资料”，选择 PDF 或 Markdown。复制、提取文字时可以取消；已完成的资料保留，失败文件逐个说明原因。
2. 点击“开始阅读”或“继续阅读”。PDF 可用目录、页码、翻页与缩放；Markdown 可点目录跳到标题。两者可切换护眼。
3. 选中同一页或同一章节的原文，点击“复制引用”，得到原文、资料名和页码/标题行号。`study-companion://source/…#…` 当前是来源标识，尚未注册系统链接协议；AI 回答的可点击引用属于下一阶段。
4. 看到“阅读位置已保存”后关闭，下次打开自动恢复；首页“最近阅读”也可以继续。阅读位置约 300 毫秒合并保存，异常退出可能丢失最后尚未保存的变更。

**首版限制：**PDF 每份不超过 50 MB、1000 页和 500 万个提取字符；Markdown 不超过 5 MB、必须为 UTF-8；每次最多 20 份，单份解析最长 60 秒。相同内容不重复入库，原件不删除、不修改；导入副本被外部修改时会阻止使用旧引用。解析在独立进程运行，失败不会把该文件标为已导入。扫描件原页可以阅读，但没有 OCR；部分扫描页会单独提示文字不全。密码 PDF 需先解锁。Markdown 原始 HTML、脚本与所有图片不加载，外链不自动打开；跨章节引用、图片阅读、助手/笔记侧栏、引用高亮与导出备份待后续实现。

## 核心学习流程（规划中）

**设定目标 → 阅读资料 → 提问求证 → 写出作品 → 获得反馈 → 复盘并安排下一步。**

用户为学习项目设定目标，将资料拆成每日任务；阅读时可以随时向 AI 提问，最终用结构化学习笔记表达自己的理解。助手依据资料给出反馈，并结合学习记录建议下一步。它默认以温柔陪伴的方式鼓励用户，也允许调整回应风格。

## 主要功能与开发范围

### 资料阅读（基础阅读已实现，AI 交互规划中）

- PDF 与 Markdown 的导入、内容去重、本机副本、目录、护眼、文字选择和进度恢复已经实现；PDF 保留原始版式，Markdown 提供标题、表格与代码排版。
- 可复制带来源的原文引用；PDF 页码和 Markdown 标题行号已持久化，供下一阶段 RAG 定位。选中提问、AI 回答引用跳转、高亮及助手/笔记侧栏仍在规划中。
- 首版优先可提取文字的 PDF。扫描件可读原页；扫描件 OCR、Markdown 图片和更多文件格式留待后续。

### 可追溯的 RAG 问答（规划中）

- 从已导入资料中检索证据，再生成回答；引用定位到 PDF 页码或 Markdown 标题。资料不足时明确说明，不编造出处。
- 结合全文检索与本地向量检索，并通过固定问答集记录检索命中率、引用准确性和失败案例，让 RAG 效果可验证、可改进。

### 小型学习 Agent 与长期记忆（规划中）

- 根据目标和资料建议学习步骤，辅助检索、解释、追问、起草笔记以及安排每日任务。
- 新增计划、更新进度或写入长期记忆前由用户确认。学习轨迹与个人偏好都可以查看、编辑和删除。
- 结构化学习笔记是默认作品。AI 给出有资料依据的已掌握点、知识缺口和改进建议；知识卡片与短测验按需生成。

### 模型接入（配置、检测与流式聊天已实现，嵌入规划中）

- 本地模型支持 Ollama；云端模型支持用户自行填写兼容 OpenAI API 的地址、密钥和模型名。本地与云端模型可平等选择。
- 普通聊天已支持逐段输出、停止、错误反馈和本地历史；真实模型质量仍待验证。资料问答与嵌入仍按阶段 2 规划推进。
- 资料检索所需的本地嵌入模型独立于聊天模型。用户无需因为选择云端聊天而安装 Ollama；嵌入模型不可用时保留关键词检索。
- 云端 API 费用由使用者自行承担，软件不内置收费模型服务。

### 计划、专注与个性化（基础签到、学习计时和偏好保存已实现，其余规划中）

- 首页日历支持查看月份与每日签到；点击“开始学习”累计今日时间，点击“暂停计时”保存并停止。签到与时间独立记录，签到不会凭空增加学习时长。计时在切换页面或最小化后继续，退出应用或系统睡眠时暂停，重启后不会自动开始；跨本地午夜的时间分别归入两天。记录每秒保存，异常退出可能丢失最后约一秒；超过 30 秒没有计时心跳时视为中断，不计入这段时间。
- 当前是手动计时器；番茄钟、自动识别阅读行为、任务关联、任务完成打卡与历史时长详情仍在规划中。浏览器预览中的签到和计时按钮不可用。
- 以学习项目和每日任务组织计划；番茄钟关联任务，结束后支持简短复盘和打卡。
- 默认使用清爽现代界面，并提供安静书房、活泼游戏化主题；回应风格可在温柔陪伴、游戏化成长和高效教练之间切换。

## 数据与发布路线

首版仅支持 Windows，不要求账号或跨设备同步。资料、阅读位置、偏好、聊天会话、签到和按日累计的学习时间已保存在本机；笔记、任务与完整导入导出仍在规划中，备份不包含 API 密钥。桌面技术为 Electron、React、TypeScript、Vite 与 SQLite，阅读器采用 PDF.js 与安全 Markdown 渲染。

开发顺序为：资料阅读与本地保存 → 模型接入和引用问答 → Agent、笔记与记忆 → 计划、番茄钟、主题和备份 → 评测与 Windows 安装包。项目使用 Git 和 GitHub 仓库管理版本；软件完成后计划通过 GitHub Releases 发布。**展示网站最后建设**，只承担项目介绍和下载入口。仓库目前为私有，公开发布前需另行确认可见性。

### 1. 已确认的产品决策

| 主题 | 第一版决定 |
| --- | --- |
| 用户与定位 | 先服务个人学习，以编程和技术资料验证体验；架构与文案保留跨学科扩展空间。 |
| 交付形态 | Windows 桌面软件优先；使用 Electron + React + TypeScript；官网最后做，不占用早期开发时间。 |
| 成本 | 开发者不承担持续服务费用，也不向用户收费；云端模型由用户自行配置并承担其服务商费用。 |
| 资料 | 首版支持可提取文字的 PDF 和 Markdown。PDF 保留原页；扫描件 OCR、Word、网页和图片以后再做。 |
| AI | Ollama 与兼容 OpenAI API 的云端接口同等重要；聊天模型可切换，RAG 的本地嵌入能力不依赖所选聊天模型。 |
| 学习成果 | 优先做带资料证据的问答和结构化学习笔记；卡片与小测按需生成，不做完整间隔复习系统。 |
| Agent 权限 | 可以自行检索和生成建议；新增计划、修改进度、写入长期记忆前必须让用户确认。 |
| 长期记忆 | 学习轨迹和个人偏好同等重要；记忆条目可查看、修改、删除，且能辨认来源。 |
| 执行与激励 | 学习项目拆成每日任务，番茄钟绑定任务；默认温柔陪伴，可切换另外两种回应风格。 |
| 视觉 | 首版默认清爽现代，同时提供安静书房、活泼游戏化主题。 |
| 数据 | 单设备本地保存，无账号和自动云同步；支持手动完整导出、导入，API 密钥不随备份导出。 |

产品体验以“资料阅读到掌握”为主线。用户导入资料并设定目标后，Agent 提出步骤；用户边读边问，写下自己的解释，得到有出处的反馈，再把未掌握的内容带入下次学习。番茄钟和打卡记录这个过程，不代替对理解程度的判断。

### 2. 技术方案与模块边界

以下是首版的实现方向，具体依赖版本在开始编码时以官方文档和锁文件为准：

- **桌面与界面：**Electron 承载 Windows 应用；React、TypeScript、Vite 构建界面。主进程负责文件、SQLite、密钥与模型请求；界面只调用明确的桥接接口。保持沙箱、上下文隔离和 CSP，界面无 Node.js 或任意路径读取。文件解析采用 Electron `utilityProcess` 独立进程，256 MB V8 堆限制、60 秒超时、进度和取消；该限制不是系统总内存上限。后台索引沿用隔离方案。
- **阅读：**PDF.js 渲染 PDF 原页并提取可选文字，引用锚点至少保存文档 ID、页码和引用片段；Markdown 按标题层级渲染，引用锚点保存标题位置。导入时将原文件复制到应用数据目录，避免原路径移动后资料失效。
- **本地数据：**Electron 内置 `node:sqlite`。主数据库版本 3 含 `app_settings`、`sources`、`source_segments`、`conversations`、`chat_turns`；旧库升级前使用 SQLite 一致性备份，迁移在事务中完成。副本用内容 SHA-256 命名，重复导入保留现有记录；锚点为 `page-N` 或 `md-line-N`，文件修改后重新导入成为新来源。学习活动独立存入 `study-activity.sqlite3` 版本 1，`study_days` 保存签到与累计毫秒；不占用阅读迁移版本。后续新增 RAG 分块、笔记、任务等。启动只探测 FTS5 能力，尚未建立全文/向量索引，不把当前文字提取称为 RAG。
- **RAG：**按页或标题结构切分资料并保留来源位置；本地多语言嵌入模型生成向量，与全文检索结果融合后交给聊天模型。回答只能引用实际取回的片段；证据不足时说明限制。嵌入模型首次使用时下载并缓存，下载失败时仍可进行全文检索和普通阅读。
- **模型适配：**通过 Ollama `/api/tags` 和兼容 OpenAI `/models` 检测模型列表；通过 `/api/chat` 的 NDJSON 与 `/chat/completions` 的 SSE 生成聊天。`chat-stream.ts` 统一增量文本、终止、超时和错误；`chat.ts` 控制会话上下文、远程发送确认、停止与保存。聊天模型与未来嵌入模型分开。云端密钥由 Windows DPAPI 加密，密文与学习数据库分开，不进入仓库、日志或备份；读取密钥只发生在主进程，界面只获知是否存在。密钥绑定规范化的服务基础地址，修改地址后不会把旧地址的密钥发给新服务。远程地址要求 HTTPS，本机回环地址支持 HTTP；模型请求禁止跟随重定向，设置超时并限制响应大小。
- **Agent：**采用受控的步骤流程，而非无限循环自主执行。工具仅包括资料检索、生成学习步骤草稿、笔记反馈、任务建议和记忆提议；每次写入计划、进度或记忆时显示变更预览并等待确认。
- **备份：**导出包含数据库、原始资料及版本信息的本地文件；导入前校验格式与版本，并先保留当前数据，防止误覆盖。密钥不进入备份。

建议的核心数据对象为 `Source`（原始资料）、`Chunk`（带来源锚点的检索片段）、`StudyProject`、`DailyTask`、`FocusSession`、`Note`、`Conversation`、`Memory`。实现时先写数据库迁移和对象约束，再接 UI；不要让界面组件直接拼接 SQL 或持有 API 密钥。

**技术路线决策（2026-09-30）：**原规划使用 Tauri + Rust。环境检查发现需要另行配置 MSVC/C++ 工具后，与用户重新讨论并选择 Electron。理由是集中使用 TypeScript，更便于学习、维护和解释 RAG 项目；接受安装包和内存占用通常较大的代价。仓库保留实际采用的 Electron 方案，不维护第二套桌面实现。后续增加嵌入模型依赖时优先选择预编译方案，并实测其下载体积、中文检索质量与 CPU 性能。

### 4. 横向质量要求

- **数据与隐私：**私人的资料、人格设定、数据库、模型缓存、备份和密钥不得提交 Git。导入资料及云端问答时，界面应清楚显示数据会留在本机还是发送给所选模型服务。
- **可访问性：**阅读、计时、确认弹窗和设置都能用键盘操作；文字对比度、焦点状态和缩放需在三种主题下可用。
- **错误处理：**文件损坏、磁盘空间不足、索引中断、模型不可达、API 限额与备份损坏都应给出可理解的恢复办法；不得把失败静默伪装为成功。
- **测试重点：**优先覆盖数据库迁移与恢复、引用锚点、检索评测、Agent 确认边界、计时中断和备份往返。不要为了覆盖率编写只复述实现的测试。
- **性能：**大文件导入和索引放在后台任务，展示进度并允许取消；阅读和计时界面不能被模型推理阻塞。
- **简历证据：**保留架构图、评测集构建方法、指标定义、失败案例和迭代记录；只展示真实测得的数据。
